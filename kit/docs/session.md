# 세션 절차 — 시작, 중간 보고, 마무리, 키트 갱신

| 항목 | 내용 |
|---|---|
| 목적 | 어떤 에이전트든 세션을 같은 방식으로 열고 닫게 한다. |
| 적용 조건 | 모든 세션의 시작과 끝, 감독의 종료 신호, 키트 갱신 요청 |
| 관련 문서 | `AGENTS.md` 「권위와 시작 순서」 · [`routes.json`](routes.json) |

## 시작

1. **상태 확인.** 작업 폴더가 Git이면 `git status`로 다른 작업자의 변경을 확인하고 보존한다.
   변경을 지우려고 reset·checkout하지 않는다.
   **자기 메모리 점검.** 자동 메모리·노트·스킬에 이 프로젝트의 규칙·취향·상태가 남아 있으면
   소유 문서(`craft/taste.md`, `BRIEF.md`, `DECISIONS.md`, `STATE.md`)로 옮기고 포인터만 남긴다.
   옮긴 것은 시작 보고에 한 줄 적는다.
2. **작업 유형 선택.** 감독의 요청을 `routes.json`의 `tasks` 표에 맞춘다. 작품을 지목했으면
   `--project`, 모델이 정해졌으면 `--model`을 붙인다.
3. **읽기.** 라우터가 낸 `read_order`를 번호 순서로 읽는다. 라우터를 못 돌리면 표를 손으로
   읽는다. 읽은 목록은 첫 보고에 한 줄로 적는다("읽은 문서: gate, doctrine, taste, guides/…").
4. **시작 보고.** 지금 어느 단계인지, 무엇을 할 것인지, 감독이 지금 정할 것이 있는지를 한
   문단으로 말하고 시작한다.

## 중간 보고

의미 있는 중간 보고에는 세 가지가 드러나야 한다. `지금 어느 단계인지`, `왜 지금 말하는지`,
`감독이 선택·확인할 것이 있는지`. 확인할 것이 없으면 그렇게 말한다. 선택지는 이미지·표로
먼저 보이고 글은 판단에 필요한 만큼만 쓴다.

감독이 취향·방향을 말하면 `AGENTS.md` 「감독의 말이 규칙이 되는 길」에 따라 층을 판별해
즉시 기록하고, 어디에 적었는지 보고한다.

## 마무리

감독이 "고생했어", "끝", "마무리하자"처럼 종료를 알리면 새 작업을 시작하지 않고 아래를 한
바퀴 돈 뒤 짧게 보고한다.

1. **프로세스.** 이 세션이 띄운 서버·프로세스가 남았는지 확인한다. 검증용은 끄고, 감독이 계속
   쓰는 것은 끄지 않고 켜져 있다고만 알린다.
2. **임시물.** 세션이 만든 임시 파일·실험 산출물 중 더 필요 없는 것을 정리한다. 감독의 파일과
   최종 결과물은 건드리지 않는다.
3. **장부.** 작품의 `STATE.md`(상태·마지막 갱신·다음 행동)와 `DECISIONS.md`를 현재에 맞춘다.
   감독의 말 중 아직 기록하지 않은 취향·규칙이 있으면 지금 기록한다. 이 세션 동안 자기 메모리에
   적은 것이 있으면 소유 문서로 옮기고 메모리에는 포인터만 남긴다.
4. **저장.** Git이면 자기 파일만 골라 커밋한다. push·공개는 승인이 있을 때만.
5. **보고.** 정리한 것, 남겨둔 것과 이유, 미완료 항목을 한 번에 정리해 전달한다.

## 키트 갱신

감독이 "키트 갱신"을 말하면:

1. `.denomcp/kit.json`의 현재 버전을 읽고 보고한다.
2. 새 키트를 받는다(MCP 서버의 `kit_update` 도구, 또는 감독이 준 압축본).
3. **바꾸는 것**: `AGENTS.md`, `docs/`, `craft/gate.md`, `craft/doctrine.md`, `craft/guides/`,
   `tools/`, 진입 표지판 파일들, `.denomcp/kit.json`.
4. **절대 덮어쓰지 않는 것**: `craft/taste.md`, `projects/`, 모든 `DECISIONS.md`, `.gitignore`에
   감독이 더한 줄, 감독이 직접 만든 파일.
5. 바뀐 파일 목록과 새 버전을 보고한다. 갱신으로 규칙이 바뀐 곳이 있으면 한 줄씩 짚는다.
