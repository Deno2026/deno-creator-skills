# MiniMax H3 R2V — 참고물로 새 장면 만들기

| 항목 | 내용 |
|---|---|
| 목적 | 인물·화풍·사물 참조 이미지를 바탕으로 새 장면 영상을 만들 때의 입력 형식과 고정값 |
| 적용 조건 | `generate-video --model minimax-h3-r2v` |
| 비적용 조건 | 시작 프레임 한 장을 그대로 움직이는 작업(그건 첫 프레임 I2V 계열 모델) |
| 관련 문서 | [생성 전 게이트](../gate.md) · [공통 연출 교리](../doctrine.md) · MCP 서버 `input_requirements` |

MCP 서버의 `input_requirements`가 최신 요구를 알려준다. 이 문서와 다르면 서버가 이긴다.

## 입력 형식 — 여섯 칸

프롬프트는 아래 여섯 칸을 이 순서로 채운다. 칸 이름은 그대로 쓴다. **본문은 영어로 쓴다.**
한국어 대사가 있을 때만 대사 태그 안에 원문으로 넣는다.

| 칸 | 담는 것 |
|---|---|
| `subject_definitions` | 참조 이미지마다 역할을 문장으로 못박는다. "`<Picture 1>` defines the face, hair and apron", "`<Picture 2>` is the place only"처럼 무엇을 가져오고 무엇을 가져오지 않는지. |
| `summary` | 첫머리에 `[reference generation]`. 장면을 한두 문장으로. |
| `retention_analysis` | 참조에서 무엇을 보존하는지(외형)와 무엇은 자유인지(자세·표정·움직임)를 나눈다. |
| `detailed_description` | `[Shot 1]`부터. 구도, 인물 위치, 빛, 카메라, 시간 순서대로 일어나는 사건. 두 번째 샷부터 `At 00:03.500,`처럼 시각을 붙인다. 첫 샷에는 시각을 붙이지 않는다. |
| `overall_soundscape` | 지속음과 사건 소리. 지속음은 낮은 한결같은 소리 1종. |
| `non_diegetic_music` | 음악. 없으면 `N/A`. |

- 원하는 화면은 긍정문으로. 부정 지시문을 쌓지 않는다.
- 대사가 있으면 화자 번호를 배정하고 태그로 감싼다. 대사가 없으면 번호를 만들지 않는다.
- 얼굴이 화면 높이의 3분의 1 이상 나오는 구도가 정체성 보존에 유리하다.
- 카메라는 한 문장에 한 동작만 쓴다("slow dolly in, no pan or tilt").

## 고정값

| 항목 | 값 |
|---|---|
| 세로 기준 해상도 | 768×1344 (32의 배수 격자라 정확한 9:16보다 아주 조금 길다. 감독 취향 장부나 작품 BRIEF가 다른 값을 확정하면 그쪽) |
| 길이 | 5~15초. 5초 미만은 만들지 않는다. 24fps 프레임 격자에 맞춘다(최소 유효 격자 124프레임 ≈ 5.17초) |
| 참조 이미지 | 실사·선명·글자 없음. 생성 영상에서 뽑은 프레임은 금지 |
| 시드 | 기본 랜덤. 고정은 A/B 비교할 때만. `STATE.md`에는 `랜덤`이라 적고 회수 때 실제 값으로 바꾼다 |

## 확인 판

- 지시가 듣는지 보는 판은 **본 해상도의 절반**(세로 384×672)으로 먼저 돌린다. 프레임 수는
  본 판과 같게 둔다(구조·타이밍은 해상도와 거의 무관하다).
- 서버가 허용하는 해상도 목록이 따로 있으면(`input_requirements`) 그 목록 안에서 가장 작은
  값을 쓴다.
- 확정 뒤 본 해상도는 한 번만 올린다.

## 함정

- 참조 역할을 문장으로 못박지 않으면 참조의 배경·소품이 화면에 새어 들어온다.
- 한 클립에 시각을 지정한 사건이 셋 이상이면 뒤 사건이 1.5~2초 밀린다. 정확한 박자는
  클립당 1~2개.
- "5초"는 124프레임(약 5.17초)이다. 정확히 5.000초가 필요하면 생성 뒤 자르는 계획을 세운다.

## 검사

- 서버가 검사 도구를 주면 오류 0을 확인한 뒤 제출한다. 경고는 읽고 이유를 적어 둔다.
- 결과 파일을 직접 열어 길이·해상도·프레임·소리를 확인하고 `STATE.md`에 판 이름·시드와
  함께 적는다.
