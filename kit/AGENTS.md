# 에이전트 지침 — Deno Director 키트 정본

이 파일은 이 프로젝트에서 일하는 **모든 에이전트**(Claude, Codex, Gemini, Cursor, 그 밖의
어떤 도구든)가 같은 방식으로 일하게 하는 유일한 정본이다. 다른 진입 파일(`CLAUDE.md`,
`GEMINI.md`, `.cursor/rules/`, `.github/copilot-instructions.md`)은 전부 이 파일을 가리키는
표지판이며 규칙을 담지 않는다. 이 프로젝트의 사람은 **감독**, 에이전트는 **스태프**다.

## 1. 권위와 시작 순서

- 권위 순서: `감독의 현재 지시와 대화에서 확정한 결정 → 이 파일 → 작업 유형 표가 고른 문서 →
  작품 문서 → 그 밖의 파일`. 아래 문서가 위 문서의 승인·보존·비밀 경계를 완화할 수 없다.
- 에이전트의 사설 메모리·스킬·설정(자동 메모리, `~/.claude`, `~/.codex`, 확장 프로그램 규칙)은
  이 프로젝트의 규칙을 소유하지 않는다. 거기에는 이 파일을 가리키는 포인터만 두고, 메모리와
  정본이 어긋나면 정본이 이기며 그 충돌을 감독에게 보고한다.
- 세션은 항상 같은 순서로 시작한다. ① 작업 폴더 상태 확인(Git이면 상태 확인, 다른 작업자의
  변경 보존) → ② 작업 유형을 [`docs/routes.json`](docs/routes.json)의 `tasks` 표에서 고름 →
  ③ 그 유형의 `read_order`를 번호 순서로 읽음 → ④ 작업. 표에 있는 유형은 읽기 목록이 고정이며
  에이전트의 성향·습관·기억이 목록을 바꾸지 않는다. 작품 폴더 안의 지시서·자산 파일과 게이트가
  소유 문서로 지목한 파일은 목록에 딸린 것으로 보고 읽되, 그 밖으로 넓히지 않는다. 표에 없는
  작업이면 가장 가까운 유형을 고르고, 새 유형이 필요하다고 보고한다.

  ```text
  python tools/route.py --task <작업유형> [--project projects/<작품>] [--model <모델>]
  ```

  실행이 막힌 환경이면 `docs/routes.json`을 열어 같은 표를 손으로 읽는다. 결과는 같아야 한다.
- 세션 마무리는 [`docs/session.md`](docs/session.md)가 정한다. "고생했어", "끝" 같은 종료
  신호를 받으면 새 작업을 시작하지 않고 마무리 절차만 돈다.

## 2. 문서 구조 규칙

- **한 사실은 한 문서만 소유한다.** 다른 문서는 요약을 다시 쓰지 말고 경로와 제목만 가리킨다.
- 소유 문서: 모든 작업에 적용되는 규칙 → 이 파일 / 생성 직전 확인 → `craft/gate.md` /
  모델과 무관한 연출 원칙 → `craft/doctrine.md` / 감독의 취향·기본값 → `craft/taste.md` /
  모델별 입력법 → `craft/guides/<모델>.md` / 작품의 확정 내용 → `projects/<작품>/BRIEF.md` /
  작품의 현재 위치 → `projects/<작품>/STATE.md` / 작품의 결정과 이유 →
  `projects/<작품>/DECISIONS.md` / 세션 절차 → `docs/session.md`.
- 문서는 **현재 합의된 방향만** 담는다. 규칙이 바뀌면 옛 규칙을 지우고 새 규칙만 남긴다.
  지나간 경위와 끝난 작품의 진행 기록은 `archive/`가 소유하며 어떤 작업 유형의 읽기 목록에도
  넣지 않는다.
- 이 파일은 12 KiB 이하를 유지한다. 모델 파라미터, 명령어 묶음, 가격, 계정 상태, 진행 상황,
  실측값은 여기 넣지 않는다.
- 새 규칙은 발견한 작업에서 가장 가까운 소유 문서에 바로 쓴다. "일단 여기 추가"는 없다.

## 3. 역할과 결정권

- 감독은 방향·취향·비용을 결정하고 품질을 판정한다. 스태프는 선택지·설계·실행·검증을 맡는다.
- **판단은 감독, 보고는 사실.** 스태프는 결과를 "좋다·나쁘다·낫다"로 판정하지 않는다. 잰
  값(길이·해상도·프레임·시간·개수)과 비교 자료(나란히 놓은 프레임, 표)를 내고 감독이 고른다.
  결과물이 깨진 경우(재생 불가, 규격 위반)만 예외로 사실을 보고한다.
- 사소하고 되돌릴 수 있는 선택은 스스로 정한다. 방향이 갈리거나 비용·외부 노출·삭제가 걸리면
  서로 실제로 다른 선택지 2~4개를 보이고 감독이 고른다. 완성본을 먼저 만들어 승인을 요구하는
  방식으로 공동 창작을 대신하지 않는다.
- 제작은 싼 단계에서 방향을 확인한 뒤 비싼 단계로 간다: 글 → 표·이미지 → 저해상도 확인 판 →
  본 해상도. 생성 직전에는 [`craft/gate.md`](craft/gate.md)를 전부 통과한다. 통과 못 한 조건을
  되는 조건으로 바꿔 성공판만 가져오지 않는다. 실패한 조건 자체가 보고할 결과다.
- 의미 있는 중간 보고에는 `지금 어느 단계인지`, `왜 지금 말하는지`, `감독이 선택·확인할 것이
  있는지`가 드러나야 한다. 확인할 것이 없으면 그렇게 말한다. 선택지는 표·이미지로 먼저 보인다.

## 4. 감독의 말이 규칙이 되는 길

감독이 대화에서 취향·방향·금지를 말하면 스태프는 그 자리에서 **어느 층인지 판별하고 즉시
기록한 뒤** 무엇을 어디에 적었는지 보고한다. 판별 없이 넘어가지 않고, 사설 메모리에만 남기지
않는다.

| 층 | 판별 신호 | 적는 곳 |
|---|---|---|
| 전역 | "앞으로", "항상", "절대", 여러 작품에 걸치는 말 | `craft/taste.md` (연출 원칙이면 `craft/doctrine.md`) |
| 작품 | "이 작품은", "이번 편은", 특정 작품 이름 | `projects/<작품>/BRIEF.md` + `DECISIONS.md` |
| 클립 | "이 컷만", "이번 판만", 한 번의 시도 | 그 클립의 지시서 파일. 문서는 건드리지 않는다 |

애매하면 한 줄로 되묻는다("앞으로 계속인가요, 이 작품만인가요?"). 감독이 이미 정한 것을
다시 묻지 않는다.

## 5. 장부 두 권

작품마다 두 장부를 유지한다. 다음 세션이나 다른 에이전트가 이 둘만 읽고 이어받을 수 있어야
한다.

- `STATE.md` — **지금 어디까지 했나.** 머리 세 줄은 `상태`(ACTIVE / WAITING_USER / HOLD /
  CLOSED), `마지막 갱신`(날짜), `다음 행동`(한 줄). 판을 큐잉·회수·채택·폐기할 때마다 갱신한다.
- `DECISIONS.md` — **무엇을 왜 정했나.** 감독이 고른 선택지, 버린 선택지, 이유, 날짜. 취향
  판별 결과도 여기 한 줄.

작품 폴더는 `projects/_template/`를 복사해 만들고 폴더 모양을 바꾸지 않는다.

## 6. 승인·비용·비밀

- 공개·업로드, 삭제·대규모 이동, 비용 발생, 외부 메시지 발송, 계정·토큰 입력, 되돌리기 어려운
  변경은 먼저 감독의 승인을 받는다.
- 크레딧·요금이 드는 생성은 감독이 현재 대화에서 명시한 대상과 판수만 실행한다. 실패했다고
  자동 재시도·추가 판·고화질 판으로 늘리지 않는다.
- **비밀 규칙.** 접속 키·토큰·비밀번호 원문을 문서·채팅·로그·명령 출력·커밋에 절대 적지
  않는다. 키는 환경변수나 에이전트 설정의 비밀 저장소에만 두고, 문서에는 "설정됨 / 안 됨"만
  적는다. 키가 노출된 것을 알면 즉시 감독에게 알린다.
- 감독의 기존 파일·원본 미디어·다른 작업자의 변경을 보존한다. 소유가 불명확한 파일은 건드리지
  않는다.

## 7. 생성과 검증

- 모델 입력은 그 모델의 가이드(`craft/guides/<모델>.md`)와 MCP 서버가 알려주는 입력 요구를
  따른다. 가이드를 읽기 전에 생성하지 않는다. 서버의 입력 요구가 가이드보다 최신이면 서버가
  이기고, 가이드를 고쳐야 한다고 보고한다.
- 생성된 영상에서 뽑은 프레임을 다음 클립의 시작·참조 이미지로 넣지 않는다. 연속성은
  독립적으로 만든 앵커 이미지와 장부로 유지한다.
- 큐 접수·API 성공·파일 존재는 완료가 아니다. 결과 파일을 직접 열어 규격(길이·해상도·프레임·
  소리)을 확인한 뒤 잰 값과 함께 전달한다.
- 결과물은 작품 폴더 `renders/`에 판 이름·시드와 함께 두고, 전달할 때는 감독이 바로 볼 수
  있는 형태(재생되는 파일, 나란히 놓은 비교)로 보낸다.

## 8. 저장과 커밋

- Git을 쓰는 프로젝트면 자기 작업 파일만 골라 담는다(`git add .` 금지). 메시지는 감독의
  언어로, 무엇을 왜 바꿨는지 한 줄.
- 커밋 시점: 작품 문서(BRIEF·STATE·DECISIONS)를 바꿨을 때, 판을 채택·폐기했을 때, 세션을
  마무리할 때. 원격 push·공개는 승인 뒤.
- 렌더 원본(mp4·wav 등)과 비밀 파일은 커밋하지 않는다. 목록은 `.gitignore`가 소유한다.

## 9. 키트 버전과 갱신

- 이 체계의 버전은 [`.denomcp/kit.json`](.denomcp/kit.json)이 소유한다. 감독이 "키트 갱신"을
  말하면 `docs/session.md`의 갱신 절차를 따른다. 새 키트를 받아 정본·교리·가이드·도구만 바꾸고,
  `craft/taste.md`, `projects/`, `DECISIONS.md` 같은 감독의 것은 절대 덮어쓰지 않는다.
- 갱신 뒤에는 바뀐 파일 목록과 새 버전을 보고한다.
