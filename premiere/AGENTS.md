# 프리미어 후반 키트 — 에이전트 지침

**이 문서가 이 폴더의 유일한 에이전트 정본이다.** Claude Code·Codex·Gemini CLI 등 어떤 에이전트든 여기서 시작해 같은 기준으로 일한다. 규칙은 이 문서와 [문서 안내판](docs/agent/README.md)이 가리키는 workflow에만 두고, 대화나 자기 메모리에 두지 않는다. 사용자가 새 기준을 말하면 해당 workflow(연출은 [채널 연출 기준](docs/agent/workflows/channel-motion-profile.md))에 그 자리에서 적는다.

## 무엇을 하는 키트인가

Premiere Pro 중심 YouTube 제작에서 컷·오디오·자막·모션·마스터 렌더·업로드·현지화·숏폼 게시를 에이전트가 대신 수행해 사용자의 개입을 줄인다. 제작 뼈대는 `컷 → 사용자 최종 컷 → 오디오·모션 → 사용자가 내보낸 SRT 교정·최종 자막 → 마스터 렌더 → 업로드 헬퍼 → unlisted+한국어 자막 → 영어 자막·전체 언어 현지화 → 사용자가 공개`다. 제목·설명·썸네일·업로드는 마스터와 독립적인 후작업이다.

**연출은 사용자의 것이다.** 이 키트는 절차·도구·품질 기준(순정값)만 준다. 어떻게 보이게 할지는 사용자와 대화하며 정하고, 정해진 것은 [채널 연출 기준](docs/agent/workflows/channel-motion-profile.md)에 기록해 다음부터 기본값으로 쓴다.

## 시작 순서

1. 이 문서 → [문서 안내판](docs/agent/README.md)의 표에서 현재 요청에 맞는 workflow와 필수 참조를 읽는다. 애매하면 `npm run production:route -- "요청 문장"`.
2. 현재 코드·live 상태로 실행한다. Premiere가 열려 있으면 project·sequence·target을 먼저 읽는다([Premiere 제어](docs/agent/workflows/premiere-control.md)).
3. 명령은 이 폴더를 cwd로 실행한다. 어떤 도구가 있는지는 `package.json` scripts와 README의 도구 표에서 먼저 확인하고, 추측으로 "없다"고 하지 않는다.
4. 설정은 세 파일이다 — `local.config.json`(이 PC의 런타임 폴더·상류 리포 경로), 런타임의 `channels.json`(채널 목록·설명 고정 블록), `youtube-settings.json`(Google OAuth 클라이언트). 없으면 [README 설치 안내](README.md)대로 만든다.
5. 제작자가 자기 환경에서 확인하지 못한 항목([README 「검증 상태」](README.md#검증-상태--무엇을-확인했고-무엇은-못-했나): 처음 설치하는 PC의 플러그인 설치, 이 폴더의 Remotion 실렌더, 소셜 실게시)은 **에이전트가 절차대로 직접 수행하고 결과로 확인한다.** "제작자가 검증하지 않았다"는 건너뛸 이유가 아니라 확인해야 할 이유다.

## 하드룰

- **자막 싱크는 사용자가 전달한 SRT의 타임코드가 정본이다.** cue-locked 교정 → 문맥 병합(envelope 안) 두 단계만 하고, 재전사·자동 정렬·재타이밍은 사용자가 명시한 범위에서만. 파일이 없으면 자막 단계만 기다린다. 세부는 [자막 제작](docs/agent/workflows/caption-production.md).
- **한 작업 단위가 끝나면 그 작업이 띄운 것을 그 자리에서 내린다.** 헬퍼 서버(3000), 프리뷰·Remotion 크롬, MCP 브리지 프로세스, GPU에 올린 모델(Whisper·Qwen). 내렸다고 말하기 전에 포트와 PID로 확인한다. 사용자가 쓰는 Premiere·브라우저는 내리지 않는다.
- **사용자의 개인 정보는 영상에 내보내지 않는다.** 실제 로컬 경로, Windows 프로필 이름, 계정·이메일·연락처. 화면 문구에는 임의 경로를 쓰고, 녹화 화면에 찍힌 것은 가림 조각으로 바꾼다.
- **확인할 수 있는 외부 사실을 학습 지식으로 단정하지 않는다.** 모델명·버전·요금·서체의 글리프는 조회·파일 검사·공식 문서로 확인하고, 못 하면 `미확인`으로 표시한다.
- **받아쓰기의 깨진 숫자·모델명을 추정해 그래픽·자막에 넣지 않는다.** 실제 오디오로 확인하거나 사용자에게 그 항목만 묻는다.
- **시각자료는 함께 나오는 발화와 직접 관련돼야 한다.** 무관한 사진의 반복·모델 간 돌려쓰기·장식용 대체를 하지 않는다([모션 제작 §5](docs/agent/workflows/motion-production.md#5-발화와-시각자료의-관련성--품질-기준)).
- **업로드 채널은 `channels.json`의 기본 채널이다.** 다른 채널은 사용자가 그 영상에 이름으로 명시했을 때만이고, 장르·폴더·이전 업로드로 추정하지 않는다.
- **시스템 기본 폰트로 새 그래픽을 만들지 않는다.** 실제 face가 로드된 렌더만 결과다([서체](docs/agent/workflows/motion-typography.md)).

## 요청의 의미와 완료 결과

- `통파일만`·`파형만`·`소리 유무만`: 실제 소리 경계만 판단한다. `컷편집`·`알아서 컷`(통파일을 주며): 무음 컷과 문장 단위 다듬기를 한 번에, 복제본에 적용. `컷은 끝`: 사용자 컷을 유지하고 다음 단계만.
- `오디오 맞춰줘`·`전체 오디오 밸런스`: 구간별 체감 음량을 맞추고 순간 피크만 리미터로. `Level만`: 정적 레벨만.
- `모션 넣어줘`: 채널 연출 기준 안에서 기획·제작·렌더·타임라인 배치까지. 기준이 비어 있으면 2~3안을 비교해 사용자가 고른다.
- `자막 만들어줘`: 전달 SRT로 cue-locked 교정본 → 문맥 병합본 → caption track 반영.
- `렌더해줘`: 현재 확정 시퀀스의 export와 결과 파일 확인까지.
- 업로드: 헬퍼 준비 → 사용자가 `완료 · 업로드 시작` → unlisted+KO → EN·현지화. `public` 전환은 사용자가 Studio에서 직접.
- 결과는 Premiere 타임라인이나 요청된 artifact에서 바로 확인할 수 있게 한다. 사용자 재생 확인은 다듬는 피드백으로 쓴다.

## 승인과 보존

- 직접 편집 요청은 지목한 범위의 cut/ripple, Level, marker/effect/property, overlay/caption placement를 포함한다. 프로젝트 저장·Save As, project item·원본 media·sequence 삭제는 사용자가 요청한 범위에서만.
- 확정된 컷·오디오·합격 구간은 다음 단계와 부분 수정에서도 보존한다. 같은 경로의 렌더 파일을 덮어쓰지 않는다.
- 공개·삭제·비용 발생·외부 메시지·계정/토큰 입력·플러그인 설치는 먼저 사용자 승인을 받는다. 로그인·비밀번호·결제는 사용자가 직접 한다.
- 숏폼 다중 게시는 `publish.json` 승인 한 번이 선택된 플랫폼의 업로드·예약·공개 승인이며, 롱폼 공개 전환과 별개다.
- 세션 종료 때 Premiere Project Manager 백업을 한 번 알린다.

## 피드백과 지침 보완

사용자 피드백이나 실제 작업에서 규칙·경로 누락을 발견하면 결과 수정과 함께 원인을 소유한 workflow와 안내판 표를 보완한다. 라우팅을 바꾸면 `node scripts/self-test-production-request-router.mjs`로 확인한다. 영상별 결정은 `productions/<slug>/`(STATE.md·STYLE_BRIEF.md·ROUTE_SHEET.md)가 소유한다.
