# 모션 제작

기본 제작 도구는 **Remotion**이다(렌더·배치 계약은 [Remotion](remotion-runtime.md)). After Effects는 사용자가 요청한 작업에만 쓴다. 연출 취향(색·서체 조합·리듬·장면 수)은 이 키트의 기본값이 아니라 **사용자와 대화하며 정하고 [채널 연출 기준](channel-motion-profile.md)에 적어 나간다.** 이 문서는 절차·계약·품질 기준만 준다.

## 1. 실행 범위

- "모션 넣어줘", "자료화면 만들어줘"는 요청 범위의 기획·source 제작·render·Premiere placement를 포함한다.
- 컷 확정 뒤에는 현재 edit을 잠그고 모션 작업을 한다.
- 채널 연출 기준이 있으면 기본으로 쓰고, 색·폰트·레이아웃·기법·장면 수는 발화와 현재 화면에 맞춰 편집자가 정한다. 기준이 비어 있으면 첫 영상에서 사용자와 2~3안을 비교해 정하고 기준 문서에 기록한다.
- 세션을 넘기는 대형 제작에는 production state와 필요한 manifest를 둔다.

## 2. 연출 메모 — 블록별 양식

코드 전에 블록(발화 묶음)마다 아래 6칸을 적는다. production의 `ROUTE_SHEET.md` 표는 같은 6칸이다.

| 칸 | 적는 것 |
| --- | --- |
| 발화 의도 | 어느 cue(타임라인 시각)에서 무엇을 말하고, 시청자가 이해해야 할 대상·관계·변화 |
| 시각 | 그것을 보여줄 화면 — 주인공 요소·문구·구도. 짧은 문구·위계(제목 vs 항목) |
| 실제 자료와 출처 | 사진·영상·화면의 원본 경로·SHA·재생 시작 시각. 발화 대상과 직접 관련된 것만(§5) |
| 화면 사건 | 등장 → 변화 → 읽는 시간 → 퇴장. 핵심 명사·숫자의 첫 가시 프레임이 cue 시작에 착지, 퇴장은 다음 cue 9~10프레임 전 시작 |
| 다음 사건 | 이 블록이 끝나며 무엇을 남기고 다음 블록·컷 경계로 어떻게 넘기는가. 덮개 아웃 근처에 사용자 V1 컷이 있으면 컷까지 덮개를 유지하고 컷 뒤 약 10프레임 동안 새 화면 위에서 걷는다 |
| 보호 영역 | 화면 점유·덮개 불투명도, 자막 자리·액자 띠 등 가리면 안 되는 곳, 원본 화면 잔존 여부 |

## 3. 제작과 검수

- **받아쓰기 초안의 깨진 숫자·버전·모델명을 추정해서 그래픽·자막에 넣지 않는다.** 실제 오디오(Whisper 참고 전사 또는 직접 청취)로 확인하거나 사용자에게 그 항목만 묻는다. 확인하지 못한 값은 화면 문구에서 빼고 `확인 필요`로 보고한다.

1. 전체 발화와 marker를 읽어 thought group을 나눈다.
2. 각 thought group에 새 구도·주인공·사건을 배치한다. 발화 속 단어·숫자·고유명사는 실제 onset에 착지시킨다. 같은 카드 재등장을 새 사건으로 세지 않는다.
3. review render를 실제 속도로 보고 visual continuity, 내부 사건 변화, 자산 다양성, 텍스트 가독성, 시작·종료 timing을 다듬는다.
4. 장면 종류별 최종 출력을 render하고 해당 경로의 검증을 통과한 결과를 현재 target track/range에 배치한다.
5. 배치 위치·duration·비대상 track을 read-back한다.

샘플 정지 프레임은 공간 검수, 연속 프레임은 이동·접점·전환 검수, 오디오와 단어 시각은 의미·발화 결속 검수에 쓴다. 실제로 수행한 검수만 기록한다. 대표 프레임·규격 검사만으로 실제 속도 전체 재생이나 사용자 합격을 보고하지 않는다.

Premiere 시퀀스를 직접 수정하는 반복 작업은 **Premiere 프로그램 모니터를 사용자 검수 화면으로 쓴다.** 스틸·`--preview` 합성 mp4·컨택트시트는 `tmp/<slug>-motion/` 아래 자체 검수용이며 최종 산출물로 보존하지 않는다.

## 4. 수정

사용자 피드백이 지목한 구간의 연출·source·render·placement를 교체한다. 합격 구간과 확정된 컷·오디오는 유지한다.

### 블록 단위 수정과 오프라인 복구

블록 ID는 `B##-<slug>`(`plans/source.json`의 `blocks`). 한 블록만 고칠 때:

1. 해당 장면 코드만 수정하고 스틸/`--preview`로 자체 검수한다.
2. **새 파일명**으로 렌더한다(`--suffix=-<변경명>`). 같은 경로 덮어쓰기는 Premiere가 항목을 오프라인 처리한다.
3. 기존 블록 클립을 ripple 없이 제거한다(`remove_from_timeline`, 다른 트랙·길이 불변 확인).
4. `premiere:capture-placement-inputs`로 읽기 전용 캡처 → `production:build-overlay-placement -- --blocks=<id> --suffix=<변경명>` → `premiere:place-overlays -- <placement.json> --dry-run` → 실제 배치.
5. 시퀀스 구조 read-back(V1/V2/A 클립 수·duration 동일, 배치 트랙 시작 프레임 일치)을 `placement/`에 남긴다.

오프라인이 된 옛 project item은 사용자 승인 전에 삭제하지 않는다. 같은 경로의 미디어를 교체한 뒤 `refresh_media`가 성공해도 디코더 캐시 때문에 다른 시각의 프레임이 보일 수 있으므로, 연출이 변하는 실제 시점 한 곳을 최종 파일과 프로그램 모니터에서 대조한다.

## 5. 발화와 시각자료의 관련성 — 품질 기준

- 사진·영상·생성 이미지·결과 화면은 각각 **어느 발화의 무엇을 보여주는지** 설명할 수 있어야 한다. 예쁘거나 이미 준비돼 있다는 이유만으로 넣지 않는다.
- 특정 모델·버전·도구의 결과, 실제 사건·성능·비교·실패를 보여주는 자료에는 해당 출처·조건이 있어야 한다. 다른 모델 출력에 이름만 바꾸거나, 생성 사진을 실제 결과 대신 붙이지 않는다.
- 생성 소재는 발화에 직접 맞는 개념·상황 설명에 쓰고, 실제 기록을 재현한 경우 재현임을 구분한다.
- 동일 사진 재사용은 같은 원본의 연속 작업·같은 작품의 여러 시점·직접 비교처럼 동일 대상이어야 할 이유가 있을 때만.
- 소재 기록에 `cue/time`, `asset`, `source/model/version 또는 생성 목적`, `이 발화에 필요한 이유`, `재사용 이유`를 남긴다.
- 전수 검수는 모든 에셋 등장 구간을 발화와 대조해 유지·교체·자료 확인 필요를 판정한다. 앞부분만 정교하게 만들거나 작업량·완료 속도를 품질 대신 삼지 않는다. 마지막 프레임 제한·루프·숨은 빈 화면으로 시간을 채우지 않는다.

### 시각자료 탐색과 능동적 생성

**발화에 필요한 자료를 정의 → 사용자의 작업·테스트 결과 탐색 → 적합성 확인 → 부족한 자료 생성 → 검수·Premiere 적용**을 기본 흐름으로 쓴다. 소재 준비와 선택을 사용자에게 떠넘기지 않는다.

- 탐색처는 `local.config.json`의 `creativeUpstreamRoot`(창작 상류 리포)와 사용자가 알려 준 소재 폴더다. 전체 디스크를 매번 훑지 않고 현재 발화의 모델명·기능·행동과 관련된 기록부터 좁힌다.
- 적합한 자료가 없으면 요청된 범위에서 현재 쓸 수 있는 생성 도구(로컬 ComfyUI 등)로 직접 만들고 모델·버전·조건을 기록한다. 새 비용·인증·공유 런타임 변경은 승인 경계를 따른다.
- 선정·생성한 자료는 발화 시점과 장면 역할에 맞춰 크롭·재생·전환을 설계하고 최종 합성까지 책임진다. 채택 자료는 production의 안정적인 에셋 경로에 확보한다.

## 6. 개인 정보

사용자의 실제 로컬 경로, Windows 프로필 이름, 계정·이메일·연락처는 영상에 내보내지 않는다. 에이전트가 만드는 화면 문구(타이핑 카드 등)에는 임의 경로를 쓰고, 녹화 화면에 찍힌 것은 글자 인식으로 훑어 가림 조각으로 바꾼다.

## 7. 서체

모션 제작 전 [서체](motion-typography.md)를 읽는다. 시스템 기본 폰트로 시작하지 않고, 실제 face가 로드된 렌더만 결과로 전달한다.
