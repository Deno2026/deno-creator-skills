# 모션 문구와 서체

새로 만드는 모션 그래픽의 제작 기준이다. **기본 폰트로 시작하지 않는다.** 장면의 목적에 맞는 실제 서체를 고르고, 그 서체가 적용된 결과를 전달한다. 어떤 서체를 쓸지는 사용자의 [채널 연출 기준](channel-motion-profile.md)이 정하며, 이 문서는 고르는 법과 검증만 준다.

## 문구와 선택 원칙

- 연출용 제목·카드·배지·단계명은 **짧고 굵은 타이포그래피**를 기본으로 한다(보통 1~4단어). 긴 설명문을 그래픽에 옮기지 않는다. 의미 없는 멋내기 문구도 넣지 않는다. 언어(영어/한국어)는 채널 연출 기준을 따른다.
- 발화 자막, 정확히 읽어야 하는 제품명·코드·UI 원문, 사용자가 지정한 문구는 해당 언어와 표기를 보존한다. 한글이 필요한 장면은 한글 글리프가 검증된 서체를 따로 고른다.
- Arial·Segoe UI·맑은 고딕·브라우저 generic sans-serif 같은 시스템 기본 글꼴로 신규 모션을 만들지 않는다. 익숙하거나 설치돼 있다는 이유만으로 한 폰트를 모든 장면에 반복하지 않는다.
- 제목, 설명 라벨, 숫자, 코드의 역할에 따라 family·실제 weight·폭·자간·대소문자·줄바꿈을 함께 정한다. 연속으로 뜨는 문구는 위계로 구분한다 — 상위(제목·키워드)와 하위(항목)는 서체·크기·색·부가 요소 중 두 축 이상이 다르고, 같은 층위의 형제는 같은 조합. 굵기만 올리거나 모든 장면을 하나의 condensed sans로 통일하는 것은 서체 선정이 아니다.

## 에이전트의 준비 책임

1. 장면에 맞는 서체를 고른다. 필요한 폰트·소재·도구를 먼저 조사하고 이용 가능한 것은 직접 준비한다. 비용·인증·공개 등 별도 승인 경계는 지침을 따른다.
2. 설치된 Adobe Fonts(구독이 있을 때)와 Google Fonts(OFL)의 후보를 함께 검토한다. 필요한 weight나 글리프가 없으면 적합한 서체를 확보하거나 선택을 바꾼다. 누락을 숨긴 대체 렌더는 금지한다.
3. 선택이 결과를 크게 바꾸면 실제 모션에 넣은 짧은 비교와 **추천안·추천 이유**를 함께 제시한다.
4. production의 연출 메모에 서체명·weight·역할·출처/라이선스·로딩 방법을 남긴다. 재사용할 파일은 `assets/fonts/`(추적하지 않음)에 준비하고 복구 방법을 기록한다.

## 서체 풀

선택 목록은 `src/lib/motion-typography/catalog.ts`, Google 원본·해시·라이선스 복구 정보는 `google-fonts.lock.json`이다. 처음에는 비어 있거나 예시만 있으니 첫 영상에서 채운다. 한글 화면 문구가 필요하면 한글 음절 11,172자를 가진 서체(예: Noto Sans KR 가변)를 넣고 cmap에서 글리프를 확인한 뒤 등록한다.

```powershell
node scripts/reference-motion/prepare-motion-fonts.mjs --verify-only   # 카탈로그의 실제 face 로드 확인(있을 때)
```

## 사용 조건과 렌더 확인

- Adobe Fonts는 PC에서 활성화해 로컬로만 쓰고 파일을 리포·assets에 복사하지 않는다. `assets/fonts/`에는 OFL 등 재배포 가능한 폰트만 둔다. 공개 서버·앱에 폰트 자체를 넣는 경우는 별도 사용 조건을 확인한다.
- 렌더는 정확한 face가 로드된 뒤에 글자 폭을 측정한다. 누락 face·지정하지 않은 폰트·지원하지 않는 문자 때문에 OS fallback이 생긴 결과는 실패로 처리한다. `font-synthesis: none`으로 합성 굵기를 막는다.
- family 문자열을 적었다는 이유만으로 적용됐다고 보고하지 않는다. 실제 렌더 엔진의 font load와 사용 face, 대표 프레임의 획·자간·잘림, 실제 속도의 가독성을 확인한다.
- 글자를 강제로 찌그러뜨리지 않는다. 문구 압축·줄바꿈·서체 폭·레이아웃을 먼저 조정한다. 절대 위치의 텍스트와 그 부모에는 필요한 폭을 명시한다.
- 같은 위치에서 문구를 교체할 때 두 문장을 동시에 페이드하지 않는다.

## 폰트 실패 진단

렌더 스틸에 대괄호 폰트명·가짜 볼드·시스템 sans가 보이거나 `FontFace.load()`가 실패하면:

1. Adobe Fonts를 쓴다면 Creative Cloud/CoreSync 프로세스가 살아 있는지 확인한다(죽으면 활성화 폰트가 통째로 사라진다).
2. 카탈로그의 실제 face 로드를 재확인한다(렌더 전 매번).
3. 그래도 없으면 같은 역할의 대체 face를 다시 고르고, 왜 바꿨는지 production `STYLE_BRIEF.md`에 적는다.
4. 조용한 fallback으로 렌더된 결과는 실패로 처리하고 다시 렌더한다.
