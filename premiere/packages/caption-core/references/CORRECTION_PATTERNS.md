# Current Correction Patterns

이 문서는 새 초안 SRT 교정 전에 읽는 현재 규칙 모음이다. 날짜별 작업 이력이나 영상별 사건 기록은 남기지 않는다.

## 적용 순서

1. 이 문서와 docs/GLOSSARY.md를 읽는다.
2. 새 영상의 전체 문맥에서 실제로 맞는 규칙만 고른다.
3. correction_preflight_digest_ko.md에 적용 규칙을 적는다.
4. final Korean SRT가 들어오면 초안 교정본과 비교한다.
5. 반복 가능하거나 사용자가 명시적으로 확정한 규칙만 이 문서에 반영한다.
6. 기존 규칙을 수정하거나 통합한다. 날짜별 행을 추가하지 않는다.

## 자주 발생하는 STT 교정

- 영상 첫 인사의 채널 화자명은 `Deno`다. 자기소개 문맥의 `진호`, `진우`, `지노`, `디노`, `DINO`, `Dino`, `DENO`는 `Deno`로 확인하며, 다른 사람 이름으로 추측해 그대로 두지 않는다. cue-locked 교정본과 사용자 검토용 SRT에 `srt_tool.py semantic-lint`를 실행한다.
- 본문 검수는 화자명·채널명과 핵심 수치·의미를 기술용어와 cue 형식보다 먼저 통과시킨다. `srt_tool.py compare`와 `compare-grouped`의 구조 PASS를 본문 정확도 PASS로 보고하지 않는다.
- 문맥상 UI/노드 작업의 "컴퓨터"는 ComfyUI 가능성을 확인한다.
- "에레뎀", "엘렌", "랜", "램"처럼 들린 표현은 문맥상 LLM, RAM, VRAM을 구분한다.
- "램 스튜디오"는 LM Studio 가능성을 확인한다.
- "올라마"는 Ollama로 표기한다.
- "제이슨"은 기술 문맥에서 JSON 가능성을 확인한다.
- "비박스"는 bbox 가능성을 확인한다.
- 사람 호칭의 "개발자님이"는 문맥상 "KJ형님이" 가능성을 확인한다.

## 문맥 판정

- 초안 교정은 화자의 말투, 강조, 의도적인 반복과 설명 순서를 보존한다. STT 오류를 고치는 범위를 넘어 문장을 요약하거나 더 그럴듯한 문장으로 전면 재작성하지 않는다.
- 수치·버전·고유명사·사건이 서로 충돌하거나 불명확하면 계산이나 문맥만으로 값을 바꾸지 않는다. 실제 발화·화면 증거로 확인하고, 확인할 수 없으면 검토 표식이나 구체적인 사용자 확인 대상으로 남긴다.
- 응답 주체가 Claude인지 GPT인지 추정하지 말고 화면과 실제 발화를 확인한다.
- 모델명, 제품명, 버전은 비슷하게 들리는 일반명사로 바꾸지 않는다.
- 아키텍처 설명에서 일반적인 "모델"로 들려도 화면에 `LLM` 역할이 명시되어 있으면 중간 처리 주체를 `LLM 모델`로 구체화한다.
- 과거 워크플로와 구조를 비교하는 문장에서는 화면과 발화로 `ComfyUI`, `LTX` 등 실제 비교 대상을 확인한다.
- 노드 안내의 "사용"과 "설치"를 구분하고, 검색어는 `Video`처럼 넓혀 쓰지 말고 화면의 `Load Video` 등 실제 노드명을 우선한다.
- 장애, 질병, 혐오, 비하로 오인식된 STT는 원래 문맥을 확인해 중립적으로 바로잡는다.
- 기술용어는 억지로 한글화하지 않고 공식 영문 표기를 유지한다.

## 구조 규칙

- 초안 원본은 그대로 보존하고, 원본과 cue 번호·타임코드·cue 수·순서가 같은 cue-locked 교정 증거본을 먼저 만든다.
- 일반 초안 교정의 타이밍 권위는 원본 SRT cue 시간 범위다. 사용자가 오디오 싱크 재제작을 별도로 요청한 보수 작업이 아니면 재전사·word alignment·오디오 파형 강제정렬·SRT 간 보정으로 새 타이밍 후보를 만들지 않는다.
- 받아쓰기 때문에 한 문장, 서술어, 조사 결합 또는 `text to video`, `Wan 2.1` 같은 한 기술 용어가 인접 cue에서 부자연스럽게 잘리면 사용자 검토용 교정본에서 한 문맥 단위로 병합한다.
- Premiere 자동 받아쓰기의 1줄 약 45자 cue는 입력 기준이다. Deno 장문 final은 인접 cue를 의미 단위로 병합한 최대 2줄이며, 짧고 독립적인 cue는 1줄로 유지한다. 출력 줄 글자 수는 하드 상한이 아니라 가독성 가이드다 — 줄 평균 45자 부근이 베스트이고 45~50자도 괜찮으며(디노 2026-09-17) 글자 수보다 맥락이 우선한다.
- 문맥 완결성과 화면 가독성이 충돌하면 2줄 가독성을 우선한다. 3~5줄짜리 긴 cue를 만들지 않는다.
- `방향성에 / 대해서`, `복잡한 / 구조로`, `공부하고 / 계신`, `할 / 수가`처럼 조사·수식어·보조용언·서술어를 분리한 경계는 문맥 병합 실패다. 최대 2줄을 넘으면 자연스러운 절 또는 정렬 어절 경계에서 다시 나눈다. 줄 글자 수는 가독성 가이드(평균 45자 부근, 45~50자도 괜찮음)이며 자연스러운 경계에서 끊는 것을 우선한다.
- `서브 그래프`, `finger inpainting workflow`, `LTX 2.5`, `Dual CFG Guider`, `manual sigma`, `Gemini Omni`, `모션 그래픽`처럼 한 이름·복합 기술어를 cue나 줄 사이에서 자르지 않는다.
- 자동 regroup는 후보일 뿐이다. 메인 에이전트가 전체 cue 경계와 줄바꿈을 직접 읽고 확정한 manifest, 검수 cue 수 일치, 남겨 둔 의존 경계의 개별 판정이 있어야 final 후보가 된다. 구조 PASS나 일부 표본 확인을 전체 문맥 검수로 보고하지 않는다.
- exact audio forced alignment를 수행한 작업은 원본 Whisper cue 경계보다 정렬된 word/display-card 순서가 우선한다. 모든 card를 정확히 한 번 소비하고 본문·순서를 보존한 상태에서 문장 완결 기준으로 재분할한다.
- 병합 cue는 첫 source cue의 시작값과 마지막 source cue의 종료값만 사용한다. source cue를 건너뛰거나 중복하지 않고, 원문 단어와 문장 순서를 다른 시간 범위로 옮기지 않는다.
- 문맥 병합은 내부 cue 경계를 제거하는 것이지 전역 offset이나 발화 범위 밖 싱크 보정이 아니다. 명백한 화자·장면 전환이나 긴 무음 구간은 넘지 않는다.
- 독립적으로 읽어도 자연스러운 cue는 cue 수를 줄이기 위해 기계적으로 합치지 않는다. 문맥 완결성과 한 번에 읽을 수 있는 길이를 함께 판단한다.
- 프레임 반올림 차이는 텍스트 교정·문맥 병합과 분리해 구조 검증에서 다룬다.
- 원본→cue-locked 교정본은 `srt_tool.py compare`, cue-locked 교정본→문맥 병합본은 `srt_tool.py compare-grouped`를 권위 검증으로 사용한다.
- final 차이 비교는 cue 번호만 맞추지 말고 삽입, 삭제, 병합, 분할 여부를 먼저 판별한다.
- 생성 음악이나 보컬 재생 구간의 가사를 음성만으로 확정할 수 없으면 가사를 만들어 넣지 않는다. `[음악 재생]`, `[보컬 재생]`은 검토용 임시 표식으로만 사용할 수 있으며, 사용자 final에서 빠졌다면 업로드 자막에는 남기지 않는다.
- final Korean SRT 문장은 다시 교정하지 않는다.
- 같은 slug에 새 final이 들어오면 가장 최근에 사용자가 final로 명시한 파일만 현행 권위다. 파일명이 비슷하거나 cue 수가 같아도 SHA-256과 전체 cue 타임코드가 다르면 새 revision이다.
- 새 final revision은 이전 clean KO, 영어 SRT, 영어 리뷰, source lock과 READY request를 자동으로 현행 사용 불가로 만든다.

## 영어 번역 전달 규칙

- 영어 번역은 final Korean SRT만 기준으로 한다.
- 이전 영어 문장도 새 final과 1:1 대응을 다시 확인한 뒤 참고 초안으로만 사용한다. 이전 영어 파일 자체를 최신 타임코드로 검증하지 않고 업로드하지 않는다.
- 한국어 cue 하나를 고립시켜 직역하지 않는다.
- 주어, 목적어, 수식어가 다음 cue에 이어지면 앞뒤 cue를 함께 해석한다.
- 의미, 말투, 기술용어, 수치가 손상되지 않았는지 별도 리뷰한다.
- 리뷰 완료 후 final KO, clean KO, reviewed EN의 SHA-256과 cue 구조를 `caption_source_lock.json`으로 고정하고 업로드 직전에 exact request 파일로 다시 검증한다.
