# 에이전트 지침 (DenoMCP 스타터 킷 v7)

이 리포는 AI 에이전트(클로드 코드·코덱스·에르메스 등)와 함께 영상·이미지를 만드는 작업장이다.
이 문서는 뼈대만 잡는다 — 어떤 순서로 일하고 어디서 사용자에게 묻는지. 무엇을 어떻게 표현할지는 사용자가 정한다.

## 읽는 순서

1. 이 문서.
2. `docs/agent/routes.json` — 작업 유형별로 어떤 문서를 먼저 읽을지 적은 표. 표에 있는 작업이면 그 문서부터 읽는다.
3. `skills/` — 들여온 제작 방법(꾸러미), 한 파일씩. 장부는 `skills/deno-kit.json`.
4. 작품 작업이면 그 작품의 `productions/<작품>/BRIEF.md`(목적·방향)와 `상태.md`(진행 상태).

## DenoMCP (연결된 MCP 서버)

- 영상·이미지 같은 창작 작업에서만 DenoMCP를 쓴다. 무엇을 할 수 있는지는 `deno_briefing`으로 안내한다.
- 업데이트는 먼저 말하지 않는다 — 홈페이지(denomcp.com/updates)에 적혀 있고, 사용자가 물으면 `deno_whats_new`로 편다.
- 워크플로·노하우(꾸러미)는 목록과 결과를 보여 주기만 하고, 사용자가 고른 것만 들인다. 먼저 나서서 권하거나 설치하지 않는다. 기존 파일은 묻지 않고 바꾸지 않는다.
- 꾸러미를 들이면 `skills/<slug>.md`로 저장하고 `skills/deno-kit.json`(장부)에 이름·판·날짜·통째로/골라서를 한 줄 적는다. 사용자가 「디노 업데이트 있어?」 하면 장부의 판과 `deno_knowhow_get`의 판을 비교해 바뀐 점만 보여 주고, 고른 것만 갱신한다.
- 꾸러미는 목적과 진행 순서를 주는 것이다. 표현·호흡·분위기 같은 취향은 사용자가 정한다 — 꾸러미의 「디노는 이렇게 한다」는 예시일 뿐 기준이 아니다.
- 유료 생성(`generate`) 전에는 `deno_estimate`로 예상 크레딧과 잔액을 안내하고 사용자 확인을 받는다.
- 참고물은 `upload_asset`으로 올리고 asset_id로 넘긴다. 결과는 `get_result`의 주소로 내려받아 `productions/<날짜_제목>/renders/`에 둔다.
- 실행은 로컬(내 PC의 ComfyUI)과 상용(크레딧) 두 갈래다. 로컬로 돌릴 수 있으면 로컬을 먼저 제안하되, 사양이 안 되면 상용으로 안내한다.
- 긴 대화가 압축되면 앞에서 읽은 문서는 요약만 남는다 — 다음 행동 전에 이 문서와 `docs/agent/routes.json`이 가리키는 지금 작업의 문서를 원문으로 다시 읽는다(`.codex/hooks.json`·`.claude/settings.json`의 훅이 그때 알림을 준다). 요약에 남은 기억으로 이어가지 않는다.
- 한 작업 단위가 끝나면 다음 작업은 새 세션에서 시작한다. 긴 작업은 진행 상태를 `productions/<작품>/상태.md`에 적어 두고 새 세션이 이어받는다 — 대화가 길수록 품질이 떨어진다.

## 작동방식

- 방향은 사용자와 정한다. 무엇을 만들고 왜 만드는지(목적·보여 줄 것·누가 보나)를 먼저 묻고 `BRIEF.md`에 적은 뒤 시작하며, 진행하다 갈림길이 나오면 그때마다 확인한다.
- 싼 단계에서 방향을 확인한 뒤 비싼 단계로 간다 — 짧고 낮은 확인 판을 먼저 보여 주고, 사용자가 좋다고 하면 본 판.
- 구현·제작 요청은 범위 확인 → 실행 → 검증 → 보고까지 자율적으로 끝낸다. 설명·진단 요청은 읽기 전용이다.
- 비용(크레딧)·외부 노출·삭제처럼 되돌리기 어려운 것은 먼저 묻는다.
- 결과물은 `productions/<날짜_제목>/`(기록은 Git, 생성 파일은 `renders/`에 두고 Git 제외), 임시 파일은 `_scratch/`에 둔다. 폴더 틀은 `productions/README.md`.
- 결과의 좋고 나쁨은 사용자가 판정한다. 파일이 생겼다는 사실과 결과가 좋다는 판단을 섞지 않는다. 편집·공개도 사용자 몫이다.

## 넘지 않는 선

- 열쇠·토큰 원문을 채팅·문서·로그에 적지 않는다.
- 사용자가 요청한 생성만 실행한다. 판수·대상을 늘릴 때는 먼저 확인한다.
- 이 리포의 기존 파일·워크플로를 묻지 않고 바꾸지 않는다(덧붙이기 포함).
