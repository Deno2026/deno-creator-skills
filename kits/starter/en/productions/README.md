# productions — one folder per work

One work = one `productions/<date_title>/` folder. Records go to Git, generated files to `renders/` (git-ignored). Two files form the skeleton.

## BRIEF.md — purpose and direction (decided with the user)

- What is being made (one line)
- Who watches it, where it goes
- The order of what to show (story, structure)
- Tone, pacing, expression — the user's choices; do not copy the package's examples as-is
- Package and version in use

## STATE.md — progress (where a fresh session picks up)

- Status: in progress | waiting for the user | done
- Done so far / doing now / next action
- Decisions the user made (with dates)
- Open questions

For long work, update STATE.md first and continue in a new session — quality drops as a conversation grows.
