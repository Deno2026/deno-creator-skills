# 생성 전 게이트

| 항목 | 내용 |
|---|---|
| 목적 | 어떤 에이전트가 어떤 모델로 만들든, 생성(큐잉·크레딧 소모) 직전에 같은 확인을 같은 순서로 거친다. |
| 적용 조건 | 영상·이미지·음악을 실제로 생성하기 직전 |
| 비적용 조건 | 이미 만들어진 결과의 회수·규격 확인·전달만 할 때 |
| 관련 문서 | 이 문서는 확인 항목과 소유 문서만 잇는다. 세부는 각 소유 문서가 가진다. |

`generate-*` 작업 유형의 첫 문서다. 라우터를 돌리지 못하는 환경에서도 이 문서 하나를 열면
빠뜨린 확인이 없는지 알 수 있다.

## 게이트

한 항목이라도 통과하지 못하면 생성하지 않는다. 통과 못 한 조건을 되는 조건으로 바꿔 성공판만
가져오지 않는다. **실패한 조건 자체가 보고할 결과다.**

| # | 확인 | 소유 문서 |
|---|---|---|
| G1 | 작업 폴더 상태를 확인했고, 작품 폴더에 `BRIEF.md`·`STATE.md`·`DECISIONS.md`가 있다. 다른 작업자의 변경은 건드리지 않는다. | `AGENTS.md` 「권위와 시작 순서」·「장부 두 권」 |
| G2 | 방향이 확정돼 있다. 새 작품·새 장면이면 서로 실제로 다른 선택지 2~4개를 먼저 보이고 감독이 골랐으며, 결과가 `BRIEF.md`와 `DECISIONS.md`에 있다. | `AGENTS.md` 「역할과 결정권」 |
| G3 | 지시가 듣는지 보는 판은 저해상도·짧은 길이로 먼저 돌리고, 확정 뒤에 본 해상도로 한 번만 올린다. 확인 판의 값은 모델 가이드 「확인 판」이 정한다. | `craft/doctrine.md` 「싼 단계 먼저」 · `craft/guides/<모델>.md` 「확인 판」 |
| G4 | 참조·시작 자산이 규격에 맞고 파일을 직접 열어 검수했다. 인물이 여러 클립에 이어지면 앵커 이미지를 먼저 확정한다(한두 샷 단발은 비적용). | `craft/doctrine.md` 「앵커와 연속성」 · `craft/guides/image-assets.md` |
| G5 | 생성된 영상에서 뽑은 프레임을 시작·참조 이미지로 넣지 않는다. 예외 없음. | `AGENTS.md` 「생성과 검증」 |
| G6 | 모델 입력이 그 모델 가이드의 형식이고, MCP 서버의 입력 요구(`input_requirements`)와 맞는다. 검사 도구가 있으면 오류 0이다. | `craft/guides/<모델>.md` · MCP 서버 |
| G7 | 길이·해상도·프레임 격자·스텝 같은 고정값을 가이드의 확정값대로 쓴다. 감독의 취향 장부와 작품 BRIEF가 다른 값을 확정했으면 그쪽이 우선한다. | `craft/guides/<모델>.md` · `craft/taste.md` · `<작품>/BRIEF.md` |
| G8 | 실행 자원을 확인했다. 서버 상태(`gateway_health` 등)가 정상이고 큐 상황을 안다. | MCP 서버 · 게이트웨이 안내 |
| G9 | 크레딧·요금이 드는 생성이면 감독이 이 대화에서 명시한 대상과 판수만이며, 비용을 밝혀 승인받았다. 비용은 문서가 아니라 서버 안내(`input_requirements`·요금 안내)에서 그때 확인한다. | `AGENTS.md` 「승인·비용·비밀」 · MCP 서버 |
| G10 | 생성 직전에 `STATE.md`에 판 이름·시드·다음 행동을 적었다(시드가 랜덤이면 `랜덤`이라 적고 회수 때 실제 값으로 바꾼다). 큐 접수는 완료가 아니다. | `AGENTS.md` 「장부 두 권」·「생성과 검증」 |

## 보고

- 게이트 결과는 표로 보고한다: 항목 · ✔/✖/해당없음 · 근거(확인한 값). 통과 못 한 항목은 그
  사실 그대로 보고하고, 대안은 그 뒤에 붙인다.
- 품질 판정은 감독이 한다. 스태프는 잰 값(길이·해상도·프레임·시간)과 비교 자료만 낸다.
