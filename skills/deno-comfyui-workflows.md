# 디노의 ComfyUI 워크플로 목록

이 꾸러미는 **지도**다. 무엇을 만들지가 정해지면 아래 표에서 줄 하나를 골라 그 꾸러미를 연다. 값·그래프·함정은 각 꾸러미에 있고, 여기에는 고를 때 필요한 것만 둔다.
어느 장비에서 어떤 크기·길이로 갈지는 사용자 GPU에서 찾는다(모든 꾸러미 공통). 디노의 장비·배분은 「디노는 이렇게 한다」.

**축은 둘이다(디노 확정 2026-09-27): 영상은 MiniMax H3, 사진은 Qwen-Image 2.1.** 사용 노하우는 이 두 워크플로를 중심으로 쓰고, LTX(리파인·공식 기본값)·H3 잠재 업스케일·오디오 검수는 그 둘을 돕는 보조편이다.

## 무엇을 얻나

- 「이런 결과를 만들고 싶다」 → 어느 워크플로인가 → 무슨 모델·노드가 필요한가 → 내 PC의 ComfyUI로 어떻게 돌리나.
- 디노가 **현재 쓰는 것**과 **실험 중인 것**, **은퇴한 것**을 가른다. 은퇴한 것은 옛 기록에 이름이 남아 있어도 새 작업의 기본으로 고르지 않는다.

## 목적

- 꾸러미가 늘어도 손님의 에이전트가 **한 장에서** 고르게 한다. 새 꾸러미가 생기면 이 표에 줄이 는다(이 문서의 판이 오른다).

## 진행 순서와 갈림길 — 고르는 순서

1. **결과의 종류**를 사용자와 정한다: 영상(소리 포함)인가, 사진·판면인가, 소리(음악·검수)인가, 이미 만든 것을 키우는가.
2. **재료**가 무엇인가: 참고물(시트·장소 판·스타일 키)인가, 정확한 시작 그림인가, 음성인가, 글뿐인가.
3. **실행은 내 GPU(로컬 ComfyUI)다.** 포터블·수동 설치는 `comfyui-agent-basics`로 바로 부리고, 데스크탑 앱(Comfy Desktop)이면 `comfyui-desktop-agent-launch`로 먼저 켠다. **크기·길이·화질 단계는 사용자 PC에서 찾는다** — 스모크 테스트(영상 5초·초안 크기, 사진 1080p급) → 사다리 → 사용자와 결정 → `MY-PC.md`에 고정. 절차는 `comfyui-fit-my-pc`. 각 꾸러미의 「디노는 이렇게 한다」 값은 디노 PC(96GB) 기준 권장값이다.
4. **싼 단계에서 확인 뒤 비싼 단계**: 초안(짧게·작게) → 사용자 확인 → 본 판. 어느 단계에서 사용자에게 보이는지는 각 꾸러미의 갈림길.
5. 여러 판을 만들면 그 작품의 `상태.md`에 판·시드·판정을 적는다.

## 은퇴 — 새 작업의 기본으로 고르지 않는다

- H3 알리바바 Acc-8Step 전용 로더 + Sol 희소 어텐션 그래프(꾸러미 v1), LightX 로라, 15+5·15초 전용 분기, 32×32 목소리 후보 실행기 — 2026-09-24 VDN 정본으로 통일하며 아카이브.
- LTX 2.5 디퓨전 영상 VAE(`ltx-2.5-video-vae-bf16`) — Conv로 고정(2026-09-23). 구형 템플릿에 이름이 남아 있어도 실행 사본에서 바꾼다.
- 픽셀 업스케일러(ESRGAN류) 단독으로 디테일을 만드는 것 — 디테일이 안 생긴다. 잠재에서 다시 그리는 두 방법을 쓴다.
- 세이지 어텐션(KJ 패치 노드 + `sageattention` 휠) — 2026-09-26 Comfy Kitchen(기동 인자 `--use-ck-attention` + 코어 `ModelAttentionBackend` 노드)으로 통일하며 은퇴. 모든 꾸러미 그래프가 Kitchen이다.
- H3 5+3(가로 1280×736 → 2560×1472, R2V·FL2VA) — 2026-09-27 R2V 1088p급 기본 7+1·액션 8+1로 정리하며 은퇴(디노 확정). FL2VA는 초안·기본 두 화질.

## 실행 — 로컬(내 ComfyUI)

- 각 꾸러미의 모델 표(배포처·파일명·크기)대로 받아 `comfyui-agent-basics` 순서로 돌린다. 데스크탑 앱 PC는 `comfyui-desktop-agent-launch`로 먼저 켠다.
- 생성 직전에는 `pre-generation-gate`의 확인표를, 결과를 받으면 `review-and-delivery`의 검수·전달 순서를 쓴다.
- 편마다 정본 파일(워크플로 JSON·도구 스크립트)이 첨부로 붙어 있다. `deno_knowhow_get`의 `files` 칸 주소로 받거나 공개 리포 `Deno2026/deno-creator-skills`(`skills/`·`workflows/<편>/`)에서 본다. 리포는 창고를 그대로 따라오는 거울이라 둘은 항상 같다(디노 2026-09-27).

## 디노는 이렇게 한다 — 예시 (참고이지 기준이 아니다)

- 장비 셋(96GB 전용 워커·96GB 메인·16GB 서브)에 용도를 나눈다: 영상 본 판은 96GB 둘, 사진과 오래 걸어 둬도 되는 영상은 16GB. 지정이 없으면 세 대를 생성 시간에 맞춰 고르게.
- **새 모델은 공식 가이드·공식 템플릿부터** 그대로 돌려 보고, 그다음 디노 방식으로 옮긴다. 프롬프트는 그 모델이 학습한 문체로, 보여 줄 것만 쓴다.
- 영상 원본은 5~15초, 배포 안내의 길이 기준은 5~10초. H3 자체 잠재 업스케일은 1088p급까지 쓰고, 그보다 크게 키우는 일은 LTX 리파인이 맡는 경우가 많다.
- 제작은 「줄거리 → 대목별 시간 → 판 개수·길이 → 참고물 → 지시문」 순서로 설계하고, 생성 직전에 같은 확인 목록(방향 확정·참고물 검수·프레임 재주입 없음·명세 원문 읽음·정본 값 그대로·장비 선택·크레딧 승인·상태 기록·공개 가능성)을 거친다.
