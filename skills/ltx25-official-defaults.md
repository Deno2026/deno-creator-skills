# LTX 2.5 로컬 실행본 — 공식 템플릿을 돌릴 때 실행 사본에 고정하는 것

이 꾸러미는 **순서와 고정값의 이유**를 준다. 무엇을 만들고 어떤 톤으로 갈지는 사용자가 정한다.
디노가 실제로 고른 장비·해상도·진행자 연출은 맨 아래 「디노는 이렇게 한다」에 예시로 두었다.

## 무엇을 만드나

- 글·이미지·음성에서 **영상+소리**(LTX는 영상과 소리를 같은 잠재에서 함께 만든다), 글→오디오, 기존 영상을 다시 그리는 편집(IC-LoRA — 재료 합성·인페인트·아웃페인트·모션 트랙·유니언 컨트롤).
- 결과 예: 디노 채널 강의 영상의 **진행자 샷**(사진 한 장 + 나레이션 음성 → 말하는 진행자, A2V), 다른 모델(H3)이 만든 영상의 리파인(그건 별도 꾸러미 `upscale-h3-4mp-5plus3` ②).

## 목적

- 공식 템플릿을 **원본 그대로 보존**하고, 실행할 때마다 **사본**에 같은 네 가지를 고정한다. 그래서 어떤 템플릿을 가져와도 큰 판이 디코드 단계에서 죽지 않고, 판마다 결과가 재현된다.
- 사용자의 워크플로 폴더는 건드리지 않는다 — 고정은 실행 사본에만.

## 진행 순서와 갈림길

### 0) 시작 — 사용자와 정해서 `BRIEF.md`에 적는다

- 갈래: T2V / I2V / A2V(음성이 시간축) / T2A / V2V·IC-LoRA 중 무엇인가. 참조(시작 이미지·음성·참조 인물)는 무엇인가.
- 길이(기준 5~10초. 더 길게 갈지는 사용자 GPU에서 확인한 뒤), 화면비, 톤(연기 크기·리듬)은 사용자.

### 1) 템플릿 가져오기

- ComfyUI 템플릿 브라우저의 **LTX-2.5 공식**(T2V/I2V Single·Two Stage Distilled, T2A, V2V ICLoRA, ICLoRA Ingredients·Inpaint·Outpaint·Motion Track·Union Control, A2V Two Stage Distilled)을 연다. 템플릿이 요구하는 ComfyUI 버전을 맞춘다.
- 원본은 그대로 두고 **실행 사본**을 만든다(UI 파일이면 UI로, API가 필요하면 화면의 Export (API)로 변환한 것). 사본 이름에 날짜·목적을 남긴다.

### 2) 실행 사본에 고정하는 네 가지

1. **영상 VAE = `ltx-2.5-video-vae-conv-bf16.safetensors`.** 이전 `ltx-2.5-video-vae-bf16`(디퓨전 VAE)은 쓰지 않는다 — 구형 템플릿에 그 이름이 있어도 사본의 영상 `VAELoader`를 Conv로 바꾼다. 같은 VAE를 인코더·잠재 업샘플러·디코더에 연결하는 그래프는 그 연결을 유지한다. 오디오 VAE는 그대로.
2. **영상 디코드는 일반 `VAEDecode`.** `VAEDecodeTiled`는 `VAEDecode`로 바꾼다. Conv VAE의 연속 convolution 처리는 타일/블렌딩과 다르다.
3. **마지막 샘플러 → `VRAM Debug`(KJNodes) → 디코드.** 옵션 `empty_cache`·`gc_collect`·`unload_all_models` 셋 다 `true`(`unload_all_models`의 기본값은 false라 반드시 켠다). 영상·오디오가 합쳐진 그래프는 **AV 분리 전에** 넣는다. 배선:

   ```text
   마지막 샘플러의 LATENT 출력 → VRAM Debug.any_input
   VRAM Debug.any_output → Separate AV Latent
                           ├─ video_latent → (Crop Guides가 있으면 그 뒤) → VAE Decode → Create Video.images
                           └─ audio_latent → Audio VAE Decode → Create Video.audio
   ```

   - 샘플러의 `output`과 `denoised_output` 중 **원래 디코더로 가던 출력**을 그대로 잇는다. `image_pass`·`model_pass`는 비운다.
   - 캔버스에 놓기만 하면 실행 순서가 생기지 않는다 — 입력·출력을 실제로 연결해야 한다. VAE 로더 → 디코더의 `vae` 선에는 끼우지 않는다.
   - 여러 번 샘플링하는 그래프는 **마지막 샘플러 뒤**에. 중간 결과를 미리보기로 디코드하는 단계가 있으면 그 단계 앞에도 넣되, 뒤 샘플링이 모델을 다시 올리는 비용은 감수한다.
   - 이 노드는 **샘플링이 끝난 뒤 디코드 공간**을 확보한다. 샘플링 도중의 메모리 부족은 이 노드로 해결되지 않는다(아래 갈림길).
4. **일반 샘플러가 기본.** 타일 샘플러는 경계·일관성을 잃으므로 여유가 있는 판에는 쓰지 않는다. 실제 메모리 부족일 때만 **별도 예외판**으로 쓰고, 자동으로 타일로 바꾸지 않는다.

그 밖에: 프레임 수는 **8n+1 격자**(예 121·241 — 격자 규칙이지 권장 길이가 아니다). 시드·프롬프트·참조·해상도·저장 파일명은 템플릿 값을 보존하고 작업에 맞게만 바꾼다. 공식 템플릿마다 정해 둔 참조 설정(MSR 배율, 편집·제어 목적의 참조)을 일괄로 덮어쓰지 않는다.

### 3) 프롬프트 — LTX 규격으로 다시 쓴다

- **다른 영상 모델용 프롬프트를 그대로 붙이지 않는다.** 공식 프롬프팅 가이드가 태그 문법·샷 리스트 형식은 넘어가지 않고 성능이 떨어진다고 명시한다. 흐르는 문단으로 다시 쓴다.
- 형식: 참조가 있으면 `Image 1: <인물·의상·화풍>, <이 참조가 맡는 것>.` 줄을 슬롯 순서대로 먼저, 그 다음 **장면 전체를 한 문단, 현재시제**. 컷은 산문으로 이름 붙인다(`The view cuts to a close-up of…`). 대사는 **큰따옴표 + 언어 명시**(`says in Korean, "…"`). 소리는 끝에 한 덩어리. 단일 컷은 4~8문장, 다컷은 2~4컷이 적정.
- **부정 프롬프트를 비워 두지 않는다.** 벤더 샘플 값: `subtitles, watermark, worst quality, blurry, jittery, distorted, inconsistent appearance`.
- 2단계(고해상도) 샘플링도 1단계와 **같은 프롬프트**. 「질감을 살려라」 같은 업스케일러식 지시는 이 모델의 관습이 아니다.
- 원하는 상태를 긍정형으로 쓴다. 금지 동작을 부정문으로 적지 않는다.

### 4) 접수·회수·검수

- 접수·진행·회수는 꾸러미 `comfyui-agent-basics`의 순서 그대로(큐잉 전 `/free` 포함).
- 검수: 실행 로그의 `VRAMdebug: free memory before/after`로 노드가 실제로 돌았는지(같은 샘플링 결과를 캐시로 재사용하면 이 노드도 다시 안 돈다), 영상 전체 디코드·프레임 수·꼬리 프레임(긴 판은 끝을 꼭 본다), 소리 길이 일치, **손가락**(진행자·인물 샷은 손 확대로 본다 — 전체 프레임 축소판으로는 안 보인다), 반복 동작(정지 화면으로는 안 보이므로 손 영역 움직임 곡선으로).

### 갈림길

- **샘플링 중 메모리 부족**: 2)의 3번이 돌기 전이라 효과가 없다. 해상도 → 길이 순으로 내려 5초·낮은 해상도에서 완주부터 확인하고 올린다. 그래도 필요한 판만 **고해상도 단계에만** 타일 샘플러를 쓰는 예외판을 따로 만든다(디노 16GB 실측: 아래 예시).
- **디코드가 몇 시간을 기어간다**: 메모리가 넘쳐도 OOM이 안 나는 Windows 드라이버 정책 — `comfyui-agent-basics` 「함정」.
- **시스템 램·Windows 커밋 한도**: 모델을 내려도 복원된 전체 프레임(CPU float32 버퍼)을 담을 램은 필요하다. GPU 여유가 늘어도 여기서 걸릴 수 있다.
- **H3 결과를 다시 그리는 리파인**: 이 꾸러미가 아니라 `upscale-h3-4mp-5plus3` ②(MSR 참조 + 오디오 얼림).

## 함정 — 모델 사실

- **레퍼런스 없이 업스케일러만 거는 것**(공식 Pixel Spatial Upscaler 단독)은 일관성이 무너진다. 다시 그릴 때는 참조를 함께 넣는다.
- LTX 2.3용 IC-LoRA·19B용 디테일러는 2.5 22B에 맞지 않는다(미검증·불일치).
- **깍지 낀 손가락을 LTX가 뭉갠다.** 인물이 두 손을 모으는 방향으로 끌리므로, 진행자·인물 샷은 손이 편하게 놓인 시작 사진과 가벼운 한 줄 동작으로 간다. 손 자세·시점·정지를 세세하게 지정하면 손바닥을 책상에 펴 대는 부자연스러운 자세, 없던 반지, 1~2초 간격의 틱 반복이 생겼다(디노 실측 2026-09-23, 아홉 클립 네 차례 재생성).
- LTX 오디오 VAE는 파형을 보존하지 않는다(멜→잠재→보코더 재합성). 다른 모델이 원본 파형에 맞춰 만든 말소리를 LTX에 통과시키면 입과 어긋나 보인다 — 그런 리파인은 최종 파일에 원본 오디오 트랙을 그대로 얹는다(`upscale-h3-4mp-5plus3` ②).
- 참조 이미지는 출력과 **같은 화면비 계열이면서 출력보다 큰 변이 있을 때 센터 크롭**된다. 그것만 피하면 흰 여백은 결과에 영향이 없었다(디노 실측 2026-09-08).

## 디노는 이렇게 한다 — 예시 (참고이지 기준이 아니다)

- 장비: 96GB 카드 두 대에서 **1080p급**(가로 1920×1088) 일반 샘플러. 16GB 카드는 명시한 시험에만.
- 16GB·RAM 32GB 실측(2026-09-23, INT8 convrot 디퓨전·Conv VAE·Dynamic VRAM, 960×544 8스텝 → 잠재 ×2 → 1920×1088 3스텝): 15.04초 저장까지 8분 31초, VRAM Debug가 보고한 GPU 여유 4.59 → 11.01GiB. 20.04초는 일반 샘플러로 2차 샘플러 OOM, **2차 3스텝 단계에만 2×2 타일**(overlap 8, hann, audio freeze)로 11분 12초 완주. 한 입력·한 장비의 결과다.
- 샘플러 **`euler` 고정**. 벤더 샘플의 `euler_ancestral`은 화면이 너무 흐려진다(디노 판정 2026-09-08).
- 진행자 A2V: 시작 사진의 손은 **그냥 올려 둔 자세**(설명하듯 든 자세로 시작하면 모델이 그 자세를 벗어나며 주먹·펴 댄 손을 만든다). 동작은 공통 한 줄 — 「책상 가장자리 근처에 손을 두고 강조하는 낱말에서 손바닥을 조금 열었다 내린다, 손가락은 편하게, 어깨·상체는 안정」. 마지막 인사 클립만 설명 구절을 인사로 바꾸고 숙임은 넣지 않는다(숙이면 두 손이 책상에 납작하게 모인다).
- 검수 도구: 손 영역 확대 시트, 손 움직임 곡선. 판정은 실제 속도로 본 디노가 한다.

## 포함되지 않은 것

- 디노의 실행 사본 생성 도구(원본을 읽어 위 네 가지를 적용한 사본을 만드는 스크립트)와 실행형 그래프 파일들 — 다음 판에 첨부한다. 절차는 위에 있으니 에이전트가 같은 변환을 손으로 또는 스크립트로 한다.
- 디노 내부의 디코더 패치·VRAM 상한 폴더(설치본 고유 조치).
