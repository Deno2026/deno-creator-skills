# 결과 검수와 전달 — 에이전트가 확인할 것과 사람이 판정할 것을 가르고, 원본 그대로 비교할 수 있게 전한다

## 무엇을 얻나

- 판마다 「무엇을 확인했고 무엇은 확인하지 않았는지」가 나뉜 짧은 보고와, 사용자가 바로 고를 수 있는 전달 묶음(원본 파일 · 이 판에서 확인할 것 · 입력 대사 원문 · 후보 이름 순서).
- 비교가 필요하면 원본별 재생과 정지 비교 자료(프레임 시트), 사용자가 맡긴 경우에만 비교 합본.

## 목적

에이전트는 영상을 연속된 흐름으로 보지 못하고 정지 프레임 몇 장으로 추측할 뿐이다. 그래서 확인할 수 있는 것(규격·디코드·어떤 장면이 나왔나·소리의 사실)과 사람이 할 판정(좋다·나쁘다·낫다)을 가른다. 그리고 결과를 고치거나 결함을 가리지 않고, 원본 그대로 비교할 수 있게 전한다.

## 진행 순서와 갈림길

1. **완료는 직접 확인한 것만.** 화면·산출물·수치를 직접 본 것만 완료라고 부르고, 못 본 것은 `UNVERIFIED`로 적는다. 생성 요청이 접수된 것과 파일이 실제로 저장된 것을 구분한다.
2. **영상은 가볍게 확인한다.** 규격(해상도·길이·프레임 수·소리 유무)과 전체 디코드, 초당 1프레임 정도의 훑어보기로 「어떤 장면이 나왔는지」와 생성이 깨지지 않았는지(검은 화면·멈춤·엉뚱한 장면)까지만 본다.
   - 좋다·나쁘다·낫다, 잔상·디테일·연기 평가 같은 품질 판정을 스스로 내리지 않는다. 선명도 지표 같은 보조 수치로 좋고 나쁨을 말하지 않는다.
   - **사용자가 특정 구간을 짚으면** 그 구간은 프레임을 잘게 쪼개 사실을 확인해 원인 대조에 쓴다. 판정은 사용자의 지적이 기준이다.
   - 사진(정지 이미지)은 에이전트도 충분히 볼 수 있으니 직접 검수한다.
   - **대사 없는 판은 소리까지** 확인한다 — 말 구간이 잡히면 시각을 적어 전달한다(`speech-check-whisper`). 전사는 판정이 아니다.
3. **보고는 확인한 범위를 나눠 말한다** — 클립 안 / 앞뒤 판과의 연결 / 확인하지 않음. 확인하지 않은 범위를 「문제없음」으로 말하지 않는다.
4. **검수와 편집을 가른다.** 기본 전달물은 **변경하지 않은 원본**이다. 오류의 위치·시각·영향을 기록해 그대로 전달하고, 대안은 설명하되 선택·적용은 사용자에게 맡긴다.
   - 임의로 자르기·샷 삭제·재배열·이어 붙이기·크롭·가림·합성·속도 변경·음향 교체로 결함을 감춘 검토본을 만들지 않는다. 비용을 쓴 결과일수록 결함까지 원본 기준으로 판정한다.
   - 「검토용」·「비교용」·「무료」·「로컬」·「원본은 보존」은 편집 권한이 아니다.
   - 생성 길이는 대략의 목표다 — 10.125초처럼 자연스럽게 나온 길이를 맞추려고 자르거나 다시 인코딩하지 않는다(정확한 맞춤 편집을 맡긴 경우만 예외).
   - 「~장면만 모아 줘」는 그 장면이 든 **원본 클립을 통째로** 모으라는 뜻이다. 한 폴더에 편집 순서대로 번호를 붙여 모은다.
   - 검수 자료(프레임 추출·접촉 인화지·정지 비교·전사·계측)는 만들어도 된다. 원본을 대체하지 않고 결함 위치를 추적하게 돕는 자료다.
5. **정리하고 전달한다.**
   - 결과는 작품의 `renders/` 한 폴더에 모은다. 마스터는 고화질로 두고, 공유용 가벼운 사본은 필요할 때 따로 뽑는다(마스터를 낮춰 겸하지 않는다).
   - 이름은 사람이 탐색기에서 구분할 수 있게 — 채택 후보 `번호_제목_확인포인트.mp4`, 탈락판 `폐기_판번호_사유.mp4`.
   - **후보 여러 개는 이름 순서(A·B·C, 1·2·3)대로 붙인다.** 추천을 앞에 두면 순서가 바뀌어 보여 사용자가 다른 판을 고른다. 추천은 설명 글에서 말한다.
   - **결과물 먼저, 설명은 그다음.** 검증이 남았어도 파일 자체를 먼저 보인다. 정지컷·비교 이미지는 영상 전달을 대신하지 못한다.
   - 판마다 **이 판에서 확인할 것**과 입력 대사 원문을 함께 준다.
   - 판정을 부탁하는 시안은 본 해상도로 준비한다(저해상도는 내부 확인용). 오래 걸리는 생성은 시작 전에 예상 시간을 알린다.
6. **A/B는 원본별 재생과 정지 비교가 기본이다.** 비교 영상 합본은 사용자가 그 편집을 맡겼을 때만 만든다.
   - 두 판은 좌우(`hstack`)에 라벨, 셋 이상은 2×2 격자(남는 칸에 레퍼런스) — 긴 가로 띠로 이어 피사체를 작게 만들지 않는다.
   - 한글 라벨은 한글 글꼴로. 합본은 한쪽 소리만 들어가니 소리가 판정 대상이면 각 단독본도 주고 합본에 어느 쪽 소리인지 적는다.
7. **소리 판정의 경계.** 자동 계측은 구간별 음량(RMS)·최대 dB·튀는 소리까지만. 대사 정확도·립싱크·음색·대사 아래 음악은 사람 귀로 넘긴다. 받아쓰기는 조용한 구간에서 없는 말을 지어낼 수 있으니 그 구간 음량과 교차 확인한다.
8. **비교 실험은 변수 하나씩.** 시드를 고정하고 한 번에 하나만 바꾼다. 결함이 사라졌는지 보는 교정 실험은 시드를 바꾼 판도 넣는다(같은 궤적의 우연과 구분). 입력이 완전히 같으면 캐시된 결과가 새 파일처럼 저장될 수 있다 — 정상보다 지나치게 빨리 끝나면 캐시를 의심한다. 스텝 수를 바꾸면 구도까지 달라질 수 있어 순수 화질 비교로 읽지 않는다.

갈림길: 무엇을 채택할지, 편집을 맡길지(맡긴다면 대상·범위)는 사용자가 정한다.

## 내용 자리 — 사용자가 채우는 칸

| 칸 | 어디에 |
|---|---|
| 판별 「확인할 것」과 판정 결과 | `productions/<작품>/상태.md` |
| 전달 폴더·이름 규칙 | 작품의 `renders/` |
| 맡긴 편집(대상·행위·범위) | 대화에서 사용자가 말한 그대로 `상태.md`에 적는다 |

## 실행 — 로컬

- 규격·디코드: `ffprobe`(해상도·길이·프레임·스트림), `ffmpeg -v error -i 파일 -f null -`(전체 디코드).
- 훑어보기·프레임 시트: `ffmpeg -i 파일 -vf fps=1,scale=480:-1,tile=5x4 시트.jpg` 같은 방식.
- 말소리 확인: `speech-check-whisper` 편 첨부 도구.
- A/B 합본(맡긴 경우): `ffmpeg -i a.mp4 -i b.mp4 -filter_complex hstack 비교.mp4`에 라벨.

## 디노는 이렇게 한다 — 예시 (참고이지 기준이 아니다)

- 마스터는 VHS 저장 crf 15(약 22~29Mbps), 공유·폰 전송용은 필요할 때 crf 23으로 따로 뽑는다.
- 채팅 앱 안에서 바로 재생되는 전달을 1순위로 하고, 판정받을 결과는 그 턴의 마지막에 다시 붙인 뒤 설명을 쓴다(긴 작업 중간에 보낸 파일은 기록 사이에 묻힌다).
- 미디어 결과를 전할 때만 결과 폴더를 한 번 열고, 문서·코드만 바꾼 작업에는 폴더를 열지 않는다.

## 포함되지 않은 것

- 다클립 연결 검수(앞뒤 판 경계 비교) — 방법을 아직 시험 중이라 편이 없다.
- 편집 자체 — 사용자의 몫이다.
