# ComfyUI를 에이전트가 다루는 법 — 디노 방식

이 꾸러미는 **순서와 확인 자리**를 준다. 어느 PC를 쓰고, 결과를 어디에 두고, 몇 대를 어떻게 나눌지는 사용자가 정한다.
디노가 실제로 쓰는 장비 배분·기동 방식은 맨 아래 「디노는 이렇게 한다」에 예시로 두었다.

## 무엇을 얻나

- 에이전트가 ComfyUI의 HTTP API만으로 **워크플로에 입력을 끼워 접수 → 진행 확인 → 결과 파일 회수 → 실제로 열어 검수**까지 한 바퀴를 끝낸다. 사람이 화면에서 Run을 누르지 않는다.
- 같은 절차가 이 창고의 로컬 갈래 전부(`minimax-h3-r2v-deno`, `upscale-h3-4mp-5plus3`, `stable-audio-3-bgm`)의 바탕이다. 각 꾸러미는 「무엇을 끼우나」만 다르다.

## 목적

- **접수 ≠ 완료.** 큐에 들어갔다·파일이 생겼다·시간이 흘렀다로 완료를 말하지 않는다. 결과를 직접 연다.
- **깨끗한 GPU에서 시작한다.** ComfyUI는 앞 판의 모델을 알아서 내리지 않는다. 그 위에 새 판을 얹으면 메모리가 넘친 채 기어가고, 그 상태에서는 중단 명령도 듣지 않는다.
- **사용자의 것은 건드리지 않는다.** 사용자의 워크플로 폴더·모델·설정은 읽기만 하고, 에이전트의 실험은 따로 둔다.

## 진행 순서와 갈림길

### 0) 시작 — 사용자와 정해서 작품 `BRIEF.md`·`상태.md`에 적는다

- 어느 ComfyUI를 쓰나: 주소와 포트(같은 PC면 `http://127.0.0.1:8188`, 다른 PC면 그 PC의 LAN 주소 — 그 PC는 `--listen`으로 켜져 있고 방화벽이 **이 PC 주소 하나에만** 8188을 열어 두어야 한다. 인터넷에 열지 않는다).
- 결과를 둘 폴더(작품 폴더의 `renders/` 같은 자리), 워크플로 정본이 어디 있나(꾸러미의 API 그래프인지, 사용자의 파일인지).
- 여러 대가 있으면 배분 규칙(어느 것이 기본, 어느 것은 조건부). 없으면 한 대.
- 폴링 간격(기본 30초 정도)과 한 판 상한 시간(넘으면 사용자에게 알린다).

### 1) 서버 확인

- `GET /system_stats` — 살아 있나, ComfyUI 버전, 기동 인자(`argv`), 장치·VRAM. 이 창고의 워크플로는 **Comfy Kitchen 어텐션**을 전제로 하니 `argv`에 `--use-ck-attention`이 있는지 본다(없어도 그래프의 `ModelAttentionBackend` 노드가 그 모델은 Kitchen으로 돌리지만, 전부 켜 두는 것이 기본. NVIDIA SM 7.5 이상·AMD RDNA3 이상에서만 — 미지원 GPU에 인자를 넣으면 서버가 안 뜬다). 업데이트 뒤에는 이 `argv`와 기동 로그의 버전 줄을 다시 본다(업데이트가 로컬 수정·인자를 되돌리는 일이 있다).
- `GET /queue` — `queue_running`·`queue_pending`. 다른 판이 돌고 있으면 뒤에 줄을 서되, 큰 판을 넣기 전에는 사용자에게 알린다.
- **ComfyUI 데스크탑(Comfy Desktop) 앱으로 쓰는 PC는 켜는 법이 다르다** — 앱 껍데기가 서버 실행을 쥐고 있어 에이전트가 첫 단계에서 막힌다. 꾸러미 `comfyui-desktop-agent-launch`의 절차로 켜고 주소를 얻은 뒤 이 문서의 2)부터 이어 간다.
- 포터블·수동 설치에서 꺼져 있으면 **사용자에게 켜 달라고 한다.** 켤 때는 로그가 보이는 콘솔 창으로 — 에이전트가 숨은 백그라운드 프로세스로 띄우지 않는다(사용자가 창을 닫는 것만으로 끌 수 있어야 한다). 사용자가 원격 기동을 맡겼을 때만, 그 PC의 로그인 세션에 **보이는 창**으로 띄운다.

### 2) 그래프 준비 — API 형식으로

- `POST /prompt`가 받는 것은 **API 형식**(노드 번호 → `class_type`·`inputs` 딕셔너리)이다. 화면에서 저장한 UI 워크플로(`nodes` 배열)는 그대로 넣지 못한다 — ComfyUI 화면의 **Export (API)** 로 변환한 정본을 쓴다. 중첩 그룹이 있는 UI 파일을 도구로 자동 변환하면 위젯 값이 빠지는 일이 있어, 검증하지 않은 변환본은 배포·공유하지 않는다.
- 자리표시자를 채운다: 프롬프트, 참조 파일명, 시드, 크기(모델 격자에 맞는 배수), 프레임 수(모델 격자), 저장 접두어(작품/장면/판 이름이 파일명에 남게).
- 시드는 기본 무작위, **재현·비교할 때만 고정**한다. 어떤 시드로 넣었는지 `상태.md`에 적는다.

### 3) 대조 — 없는 것은 대체하지 않는다

- `GET /object_info/<class_type>` — 노드가 있나, 필수 입력이 무엇인가, 선택지(모델 파일 드롭다운)에 그 파일이 있나.
- 노드·모델이 없으면 「비슷한 파일로 대체」하지 않고 **정확한 원본**(꾸러미의 모델 표: 배포처·파일명·크기)을 사용자에게 알리고 설치·다운로드는 사용자가 정한 대로 한다. 파일은 크기·SHA256으로 대조한다.

### 4) 참조 업로드

- `POST /upload/image` (multipart, 필드 이름 `image`) → 응답의 `name`을 `LoadImage.image`에 넣는다. 오디오(`LoadAudio`)·영상(`LoadVideo`)도 같은 창구로 올린다.
- 이미 입력함에 있는 파일이면 이름만 준다. 결과 폴더의 파일도 경로를 주면 다시 올라간다 — 이사할 필요 없다.
- **생성된 영상의 프레임을 다음 판의 참조로 넣지 않는다.** 참조는 독립 자산이다.

### 5) 큐 비우기·메모리 내리기

- `GET /queue`가 비었는지 본다.
- 앞 판의 모델이 올라가 있으면 **큐잉 직전에** `POST /free` 본문 `{"unload_models": true}` — 캐시는 두고 VRAM만 내린다. 다른 구성(다른 모델·다른 디코드 방식)으로 바꿀 때 특히 필수다.
- 다른 판이 도는 중이면 `/free`는 그 판을 끊지 않는다(ComfyUI는 한 판을 끝낸 뒤 다음 판을 꺼내기 전에 처리한다). 그래서 **내 판이 바로 다음 차례일 때 걸고, 내 판이 돌기 시작하면 한 번 더** 건다.

### 6) 접수

- `POST /prompt` 본문 `{"prompt": <API 그래프>}` (원하면 `client_id`도) → 응답의 `prompt_id`가 작업 번호다.
- 접수 직전에 `상태.md`에 판 이름·시드·다음 행동을 적는다. 접수는 완료가 아니다.

### 7) 진행

- `GET /queue`에 있으면 대기·실행 중, `GET /history/<prompt_id>`에 항목이 생기고 `outputs`가 차면 끝. 30초 간격 정도로 본다.
- **진행률 로그를 판정 근거로 쓰지 않는다** — 서버 로그의 진행 막대는 수십 분 늦게 찍히기도 한다. 멈춘 듯하면 계측으로 가른다: GPU 온도·전력·사용률이 높으면 정직하게 계산 중, 저온·저전력에 오래 걸리면 메모리가 넘쳐 시스템 램으로 흘러넘친 판(아래 「함정」).
- 실패는 `/history/<id>`의 `status.messages`에 남는다. 메모리 부족이면 해상도 → 길이 순으로 내려 **5초·낮은 해상도에서 완주**부터 확인한 뒤 올린다.
- `POST /interrupt`는 정상 상태에서만 듣는다. 넘친 채 기어가는 판은 프로세스를 끝내는 것 말고 회수 방법이 없다 — 그래서 5)가 필수다.

### 8) 회수

- `/history/<id>`의 `outputs[<노드>]`에 `images`·`gifs`·`videos`·`audio` 항목이 있다. 각 항목의 `filename`·`subfolder`·`type`으로 `GET /view?filename=…&subfolder=…&type=output`을 받아 작품 폴더에 저장한다.
- 원본 한 개를 그대로 둔다 — 자르거나 다시 인코딩한 사본을 원본 자리에 두지 않는다.

### 9) 검수 — 파일을 연다

- 영상: 프레임 수·길이·해상도·fps가 장부와 같은가, 시작·중간·끝 프레임 콘택트 시트, 정상 속도 재생, 소리 유무. **전 구간이 노이즈로 나오는 실패는 큐 성공·실행 시간·파일 존재로는 못 잡는다.**
- 이미지: 지정한 글자·개수·구도, 손, 알파 채널.
- 소리·대사가 있으면 받아쓰기로 존재 여부만 확인하고, 립싱크·발음·품질 판정은 사용자가 듣고 한다.
- 실패도 결과물이다 — 어디가 어긋났는지 적고 다음 판을 정한다.

### 10) 정리

- 작업 단위가 끝나면 `POST /free` `{"unload_models": true, "free_memory": true}`로 GPU를 돌려준다(사용자가 다른 일에 쓸 수 있게). 큐잉 직전(5)에는 캐시를 두고 VRAM만 내리지만, 끝낼 때는 캐시까지 비운다 — `unload_models`만 보내면 할당 캐시가 GPU에 남아 대기 0인데도 VRAM이 차 있다(디노 실측 2026-09-28: 전용 워커에서 H3 1088p 판 뒤 19.2GiB → `free_memory`까지 보내자 2.7GiB, 작업 전 수준).
- 내렸다고 말하기 전에 VRAM이 작업 전 수준인지 본다(`GET /system_stats`의 `vram_free`, 또는 `nvidia-smi`). 사용자나 다른 작업이 쓰는 서버는 대기줄이 비어 있을 때만 비운다.
- 임시 파일·중간 산출물은 작품 폴더의 정해진 자리에만, 루트에 흩뿌리지 않는다.
- 사용자의 워크플로 폴더는 읽기 전용이다. 에이전트가 만든 실험 그래프는 그 폴더의 `test/` 하위에 `날짜_목적_에이전트.json`처럼 누가 언제 왜 만들었는지 드러나게 둔다. 남길 가치가 있으면 사용자가 정본으로 올린다.

### 갈림길

- **여러 대에 나눌 때**: 장비마다 일꾼 하나, 판을 하나씩 꺼내 준다. 느린 장비는 남은 판이 적으면 빠지고, 필요한 모델이 없는 장비는 합류하지 않는다. 한 대가 논다고 전부 몰아넣지 않는다(느린 한 대가 다 뽑으면 하루가 간다).
- **다른 PC의 ComfyUI**: `--server` 하나만 바꾸면 업로드·큐·회수가 전부 API로 끝난다. 공유 폴더가 없어도 된다. 그 PC의 출력 폴더는 그 PC 기준이다.
- **사용자가 화면에서 Run을 누르는 판**: 그래도 5)의 `/free`는 같은 이유로 필요하다.

## 실행 — 로컬(내 ComfyUI)

**첨부 — 도구 둘(파이썬 3.10+, 표준 라이브러리만):** `status.py`(대기줄 전체 또는 작업 번호 하나의 상태·결과 목록, `--server`로 다른 PC) · `fetch.py`(끝난 작업의 결과물을 `_scratch/renders/`로 내려받기, `--out`). 큐 넣기는 워크플로 편의 첨부에 있다(H3 `queue.py`·`lightx_i2v.py`, 배경음 `music_queue.py`). `deno_knowhow_get`의 `files` 칸 주소로 받는다(로그인 없음, 판이 바뀌면 sha256도 바뀐다). 공개 리포 `Deno2026/deno-creator-skills`의 `skills/comfyui-agent-basics/`에 같은 파일이 있다.

이 문서의 절차 그대로. 상태·회수는 첨부 스크립트(`status.py`·`fetch.py`), 큐 넣기는 워크플로 편의 첨부를 쓰고, 없는 것만 에이전트가 작품 폴더에 만든다(입력: 그래프·자리표시자 값·참조 경로 / 출력: 작업 번호·결과 경로·검수 시트). 포터블·수동 설치는 그대로, 데스크탑 앱은 `comfyui-desktop-agent-launch`로 켠 뒤 같은 절차.

## 함정 — 실측으로 확인된 것

- **캐시된 모델은 알아서 안 내려간다.** 새 판이 들어와도 로그에 `0 models unloaded`가 찍히고 그 위에 얹는다. 그러면 메모리가 가득 찬 채 스래싱에 들어가고 `/interrupt`도 안 듣는다. 판마다 `/free`.
- **Windows·NVIDIA 드라이버의 「CUDA 시스템 메모리 대체」가 켜져 있으면 넘쳐도 OOM이 안 난다** — 시스템 램으로 흘러넘쳐 몇 시간을 기어가고, ComfyUI의 「OOM이면 타일로 재시도」 폴백이 영원히 안 걸린다. 큰 디코드가 GPU 사용률 10%대로 멈춘 듯 보이면 이것이다. 조치는 둘 중 하나: 드라이버 제어판에서 그 정책을 「선호하지 않음」으로 두거나, ComfyUI 프로세스의 PyTorch 할당 상한을 물리 VRAM으로 거는 작은 커스텀 노드 폴더(노드 없이 기동 때 `torch.cuda.set_per_process_memory_fraction`을 부르는 파이썬 한 파일)를 둔다 — 코어 파일·기동 인자를 안 건드려 업데이트에 꼬이지 않는다(디노 실측 2026-09-09: 같은 2016×1152·289프레임 LTX 디코드가 상한 없이는 공유 메모리 35GB로 기어가고, 상한을 걸면 OOM → 자동 타일 재시도로 115초 완주).
- **정체 판정은 로그가 아니라 계측이다.** GPU 60~72℃·전력 높음·사용률 100% = 정직 연산. 저온·장시간, 또는 시스템 `Memory\Pages/sec`가 수천 이상 = 스와핑.
- **업데이트가 로컬 수정을 지운다.** 업데이트 배치·태그 체크아웃은 HEAD를 옮겨 로컬 패치가 통째로 사라진다. 업데이트 뒤 기동 로그의 버전 줄과 `argv`를 확인하고, 필요한 패치를 다시 얹는다.
- **파일 받기가 머리만 오고 멈춘다(Windows).** ComfyUI는 `/view`를 Windows TransmitFile로 보내는데 일반판 Windows는 이것을 시스템 전체에서 동시에 둘만 처리한다. 앞부분만 읽고 멈춘 재생기 연결 둘이 그 자리를 쥐면 모든 `/view`가 본문 없이 멈춘다(JSON 창구는 정상이라 「살아 있는데 파일만 안 온다」로 보인다). 그 연결을 끊으면 풀리고, 근본 조치는 기동 환경변수 `AIOHTTP_NOSENDFILE=1`(aiohttp가 일반 쓰기로 보낸다).
- **기동 배치 파일은 영문(ASCII)만.** 한글 Windows의 cmd는 배치를 콘솔 코드페이지로 읽어 UTF-8 한글 주석이 있으면 줄을 건너뛰고 주석 조각을 명령으로 실행한다.
- **업스케일·디코드는 시스템 램도 본다.** 픽셀 업스케일 노드는 결과 배치를 CPU 메모리에 통째로 잡는다(10초·243프레임을 4배로 키우면 약 19GB). 직전 판의 모델이 램에 남아 있으면 조용히 실패한다 — 소요 시간이 평소의 절반 이하면 실패를 의심하고 출력 파일을 직접 본다.
- **큐 접수·파일 존재·음성 인식 한 번으로 합격을 주장하지 않는다.**

## 디노는 이렇게 한다 — 예시 (참고이지 기준이 아니다)

- 장비 셋: 전용 생성 워커(96GB 카드, 상시) + 메인 PC(96GB, 로컬 LLM과 GPU를 나눠 씀) + 16GB 서브 PC. 지정이 없으면 생성 시간을 대충 따져 세 대에 나눠 넣는다. 사진은 16GB에서도 금방 나오고, 영상은 오래 걸어 둬도 되는 판(교육숏츠 등)을 16GB에 준다.
- 기본 장비는 전용 워커 — ComfyUI 전용이라 다른 확인 없이 넣는다. 메인 PC는 **로컬 LLM(vLLM·SGLang)이 떠 있지 않을 때만** 넣는다. 그 밖의 점유 주인 조사는 하지 않는다 — 확인은 「두 장비 큐 상태 + 메인의 LLM 유무」를 한 줄로 찍는 스크립트 한 번이다.
- ComfyUI는 Easy-Install 포터블 구조, 기동 배치를 **보이는 콘솔**로. 어텐션은 Comfy Kitchen으로 통일(2026-09-26) — 96GB 카드의 기동 인자 예: `--use-ck-attention --enable-dynamic-vram --vram-headroom 4 --disable-pinned-memory`. 16GB 카드는 `--use-ck-attention --enable-dynamic-vram --vram-headroom 1.6`에 pinned는 켠 채, `--fast`는 넣지 않는다(2026-09-03 실측: `--fast`가 있으면 headroom이 무력화돼 VRAM 97%로 차고 스로틀링).
- 로컬 LLM으로 에이전트 세션을 돌릴 때는 큐잉 뒤 완료까지 **대기 전담**(추론·대량 판독을 하지 않는다) — 토큰 생성이 샘플링의 병목이 된다.
- 폴링 30초. 정체는 `nvidia-smi` 전력·온도와 `Pages/sec`로 가른다.
- 발화 검수는 귀 대신 전사로: Mel-Band RoFormer로 목소리만 분리한 뒤 Whisper large-v3(터보 금지)로 원고와 대조, MISS 문장만 슬라이스 재전사.

## 포함되지 않은 것

- 어느 PC에 넣을지 고르는 장비 배분 스크립트와 마감(2차 가공) 스크립트 — 디노 장비 규칙이라 넣지 않는다. 상태·회수·큐 도구는 첨부로 있다.
- 디노 장비의 주소·열쇠·폴더 경로.
