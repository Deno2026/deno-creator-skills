# 프리미어 자막 2단계

**싱크는 사람이 이미 잡았다.** Premiere 받아쓰기의 타임코드는 실제 발화와 잘 맞고, 에이전트가 파형·정렬기로 다시 잡으면 오히려 깨진다(실증: 정렬기 타이밍으로 cue를 재분할해 싱크가 밀린 사고). 그래서 에이전트의 몫은 **문구**와 **읽히는 단위**다.

## 무엇을 만드나

- 1단계 cue-locked 교정본: cue 수·순서·타임코드 그대로, 문구만 고친 SRT.
- 2단계 문맥 병합본: 인접 cue를 합쳐 한 번에 읽히는 단위로 만든 SRT(검수·게시 track). 최대 2줄.
- 게시용: 최종 한국어(`final-ko.srt`), 스타일 태그 없는 clean KO, 같은 타이밍의 검수된 영어.

## 순서

1. **입력 확인.** 사용자가 지정한 SRT와 대상 시퀀스. 파일이 없으면 요청하고 자막 단계만 기다린다 — 열린 caption track·과거 산출물·전사 결과로 대체하지 않는다.
2. **1단계 교정.** 원본을 보존하고 번호·순서·시작·종료를 고정한 채 오탈자·고유명사·띄어쓰기만 고친다. 로컬 Whisper large-v3로 **전체 발화를 한 번 전사해** 본문을 이어 붙인 글자 단위 diff로 누락·오인식을 찾고, 차이마다 수정/유지/미확인을 판정해 표로 남긴다(받아쓰기가 빠뜨린 영문 토큰·숫자·모델명 복원이 목적; Whisper의 무발화 환각과 표기 규칙 차이는 유지). 두 소스가 일치해도 끝이 아니다 — 에이전트가 전체 문맥을 읽고 어색한 조사·어순·빠진 단어를 직접 고친다. `srt_tool.py compare`로 구조 보존을 검증.
3. **2단계 병합.** 받아쓰기의 「1줄 약 45자」 분할은 입력 기준일 뿐이다. 조사·수식어·서술어·한 기술 용어(`LTX / 2.5`)를 끊어 놓은 인접 cue 1~3개를 한 문장 또는 한 번에 읽히는 단위로 합친다. 병합 cue의 시작은 첫 source cue 시작, 종료는 마지막 source cue 종료만 쓰고 모든 source cue를 순서대로 정확히 한 번 포함한다. 화자·장면 전환, 1.5초 넘는 내부 무음은 넘지 않는다. 표시는 cue당 최대 2줄, 줄 글자 수는 하드 상한이 아니라 가독성 가이드(평균 45자 부근, 45~50자 괜찮음, 맥락 우선). 짧고 독립적인 cue는 기계적으로 합치지 않는다. `srt_tool.py compare-grouped --max-line-chars 50`으로 envelope·포함·줄 수 검증, `validate-srt --strict --max-duration 12 --max-line-length 50`.
4. **반영.** 반입 전용 사본(경계를 의도한 프레임 시작 이상인 최소 밀리초로)을 캡션 트랙으로 넣고 project·sequence·cue 수·V/A duration을 되읽는다. 병합본은 경계 검사가 켜진 모드로 넣는다(경계 검사를 끄는 옵션은 병합본에 쓰지 않는다). 폰트·크기·Track Style은 공개 API 밖 — `[스타일 적용 필요]`로 한 번만 알린다. 새 트랙은 기본 스타일로 들어와 긴 줄이 한 번 더 꺾여 보이므로 줄 수 판정은 사용자 스타일 적용 뒤에.
5. **확정.** 사용자가 문구·싱크를 확정하면 그 revision을 `final-ko.srt`로 고정하고 clean KO와 영어를 만든다. 사용자가 트랙을 직접 다듬어 "이게 최종"이면 저장된 `.prproj`에서 추출한다(UXP에 캡션 텍스트 읽기 API가 없다).

## 갈림길

- 사용자가 특정 시각의 싱크 문제를 지목했다 → 그 cue와 인접 cue만 실제 파형에서 확인해 고친다. 여러 구간 반복이거나 `전수조사`를 말했다 → 그때만 정렬기·파형을 진단 자료로 쓴다.
- "SRT 없이 새로 전사해"라고 명시했다 → Whisper 전사에서 token 순서·실제 발화 시간을 보존하며 의미 단위로 cue를 만든다(최대 2줄, 12초 상한).
- 자막을 읽다 협찬 신호(추적 링크·프로모션 코드·"광고 포함")가 보인다 → 그 자리에서 캠페인 브리프를 요청하고 자막 작업은 계속한다.

## 함정(실측)

- Whisper VAD를 켜면 실제 발화 23초를 무음 처리한 적이 있다 → VAD는 끈다.
- 받아쓰기와 Whisper가 둘 다 같은 오류를 내기도 한다('못 믿어 / 와가지고' → 실제 '못믿어가지고'). 소스 일치는 시작이지 끝이 아니다.
- Premiere import는 마지막 cue 종료를 1프레임 줄일 수 있다 → 반입 사본의 마지막 종료 전송값만 보정하고 원본 타임코드는 두지 않는다.
- 두 검증 도구의 기본값(7초·42자)은 병합 이전 값이라 정상 병합 cue를 오류로 센다 → 옵션을 준다.

## 디노는 이렇게 한다 — 예시

- 실제 결과: 123 source cue → 75 문맥 cue(1줄 40·2줄 35). 최근 롱폼은 cue의 약 절반이 2줄.
- 표기 규칙과 용어집은 자기 채널 것으로 채운다(모델명·도구명의 영문 표기 유지 등).

## 포함되지 않은 것

- 자막 디자인(트랙 스타일), 번인 자막 렌더, 교육숏츠의 TTS 기반 번인 자막(다른 편).
