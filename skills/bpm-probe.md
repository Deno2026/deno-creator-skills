# 템포(BPM) 측정 — 영상의 박자와 만든 곡의 박자를 숫자로 재서 맞춘다

## 무엇을 얻나

- 파일 하나에 대해: 길이, ① 자기상관 후보, ② 빗살 정합 후보, 판정(수렴/불일치), 최종 BPM과 한 마디(4박) 길이. `--profile`이면 4초 구간별 세기(곡의 흐름).
- 예: `[판정] 자기상관 96.0 / 빗살 96.2 → 수렴` · `최종 96.20 BPM 한 마디(4박) 2.49초` · `프롬프트에 적을 값: 96 BPM`.

## 목적

배경음을 영상의 박자(춤·컷 전환)에 맞추려면 양쪽 템포가 숫자로 있어야 한다. 곡을 만들 때 프롬프트에 넣을 BPM을 정하고, 만든 곡이 실제로 그 템포인지 되짚는다. 붙일지·어디에 맞출지는 편집에서 사용자가 정한다.

## 진행 순서와 갈림길

1. **영상(또는 참고 곡)의 템포를 잰다.** 영상은 소리만 뽑아 잰다(임시 파일은 지운다).
2. **두 방법이 수렴하면 그 값.** 불일치면 배수 관계인지 본다(96과 192처럼) — 낮은 쪽이 대개 실제 템포. 배수도 아니면 `--lo/--hi`로 범위를 좁혀 다시 잰다(예: 춤 영상 80~140).
3. **배경음을 만들 때** 프롬프트에 「… at 96 BPM」처럼 적는다(`stable-audio-3-bgm`·`stable-audio-3-prompting`).
4. **만든 곡을 되짚어 잰다** — 모델이 프롬프트의 BPM을 정확히 지키지 않는 일이 흔하다.
5. **영상 BPM·곡 BPM·한 마디 길이를 함께 사용자에게 넘긴다.** 컷 길이를 마디에 맞출지, 곡을 늘일지는 편집에서.

갈림길: 「빠르게/느리게」 같은 박자 감각은 수치가 아니라 사용자가 정한다. 도구는 잰 값만 낸다.

## 내용 자리 — 사용자가 채우는 칸

| 칸 | 어디에 |
|---|---|
| 영상 BPM·곡 BPM·마디 길이 | `productions/<작품>/상태.md` |
| 탐색 범위(`--lo/--hi`) | 명령줄 |

## 실행 — 로컬

**첨부 —** `bpm_probe.py`(파이썬 3.10+, `numpy`·`scipy`, `ffmpeg` PATH). `deno_knowhow_get`의 `files` 칸 주소로 받는다(로그인 없음, 판이 바뀌면 sha256도 바뀐다). 공개 리포 `Deno2026/deno-creator-skills`의 `skills/bpm-probe/`에 같은 파일이 있다.

```bash
pip install numpy scipy
python bpm_probe.py "dance.mp4"               # 최종 BPM + 마디 길이
python bpm_probe.py "dance.mp4" --profile     # 4초 구간별 세기(곡 구조)
python bpm_probe.py "bgm.mp3" --lo 80 --hi 140
```

- 영상은 ffmpeg로 22.05k mono wav로 뽑아 잰다. wav를 주면 그대로 잰다.
- ① 자기상관은 소리 변화량이 몇 초마다 되풀이되는지, ② 빗살 정합은 후보 BPM의 박자 격자에 타격음이 얼마나 몰리는지. 둘이 같은 값(또는 정확한 배수)이면 믿을 만하다.

## 함정 — 실측으로 확인된 것

- 배수 관계(반박·두 배) — 낮은 쪽이 대개 실제. 최종값은 85~170 범위로 접어(fold) 낸다.
- 타격음이 약한 곡(앰비언트·패드)은 두 방법이 갈린다 — 범위를 좁히거나 사람이 박자를 세는 편이 빠르다.
- 생성 모델은 프롬프트의 BPM을 정확히 지키지 않는다 — 되짚어 재기 전에 「맞췄다」고 말하지 않는다.

## 디노는 이렇게 한다 — 예시 (참고이지 기준이 아니다)

- 춤·리듬 편집 영상은 먼저 재서 BPM을 프롬프트에 넣고, 만든 곡을 되짚어 잰 값과 영상 값을 나란히 적어 넘긴다. 붙이는 것은 편집(프리미어)에서 디노가 한다.

## 포함되지 않은 것

- 비트에 맞춘 자동 컷·마커 찍기 — 편집 도구의 몫.
- 곡 생성 자체 — `stable-audio-3-bgm`.
